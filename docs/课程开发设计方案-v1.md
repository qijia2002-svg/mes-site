## 0. 设计假设

1. **目标受众**：以「戚家硕」（SCADA 运维 4 车间 + MES 设备联调 + PLC 现场经验）为首要画像，目标岗位为 **MES/SCADA 实施工程师**；平台内容同时可服务「有 MES 使用/运维经验、想转实施岗」的通用学员。
2. **课程载体**：完全复用平台现有数据模型（topics → chapters / questions / sql_exercises / fault_scenarios / learning_paths / certifications），**零后端改动**为原则。
3. **内容风格**：延续现有「一句话理解 → 结构图 → 现场对应 → 观察任务 → 面试能讲」的实战风格，拒绝纯理论堆砌。

### 1.2 体检结论（五个关键缺口）

1. **验证闭环只覆盖 3/7 核心课**：主题 4-7（ERP/MES/SQL/PLC）只有理论，没有测验和实操 → 学没学会无法验证（柯氏 L2 缺失）。
2. **SQL 实训量级不达岗标**：实施工程师面试必考 SQL（JOIN/GROUP BY/子查询/日期处理），现仅 6 题且集中在工单/BOM/报工三主题。
3. **布鲁姆层级停留在「记忆/理解/应用」**：无 fault_scenarios（分析/评估）和沙盒搭建（创造）→ 高阶能力无法训练与举证。
4. **路线图重叠**：rm-500「MES 实施工程师学习路线图」与 rm-502「实施工程师学习路线图」定位几乎相同；rm-503 是个人定制（应保留，其余应差异化）。
5. **认证与评价体系为空**：certifications 表建了没用 → 学习路径缺少「完成标志」，激励与能力凭证缺失。

## 3. 目标受众与岗位能力模型

### 3.1 岗位画像：MES/SCADA 实施工程师

| 能力域 | 具体能力 | 平台对应内容（现 / 补） |
|---|---|---|
| C1 业务理解 | 生产形态（ETO/MTO/MTS/离散/流程）、ISA-95 分层、ERP/MES/SCADA 边界 | 主题 4/5 ✅（补测验） |
| C2 系统配置 | 基础数据、BOM/工艺路线/工单配置、参数维护 | 主题 1/2/3 ✅（补场景） |
| C3 数据能力 | SQL 查询、数据核对、追溯分析、报表取数 | 主题 6 + SQL 实训（**重点扩容**） |

### 3.2 课程地图（能力 × 布鲁姆层级）

```
L1 认知层（记忆→理解）     ERP 原理 · MES 核心模块 · 生产形态      → 主题 4/5
L2 执行层（应用）           工单 · BOM · 报工 · SQL 基础            → 主题 1/2/3/6
L3 分析层（分析→评估）     质量追溯 · 设备稼动率 · 数据核查 · 排障  → fault_scenarios
L4 综合层（创造）           工艺路线搭建器 · 实施项目实战            → SimulatorPage
```

## 4. 单课设计规范（每主题 = 一个完整学习闭环）

### 4.1 学习目标（ABCD 格式 + 布鲁姆动词）

```
受众(A)：有 MES 使用/运维经验的学员
行为(B)：…（布鲁姆动词，见下表）
条件(C)：在平台 SQL 沙箱 / 排障沙盘 / 章节测验中
程度(D)：…（可量化标准，如 ≥80% 正确、SQL 结果集与答案哈希一致）
```

**布鲁姆动词选表**（按层级）：

| 层级 | 章节（theory） | 测验（quiz） | SQL 实训 | 排障场景 |
|---|---|---|---|---|
| 记忆 | 定义/列出/识别 | 单选/判断（事实） | — | — |
| 理解 | 解释/描述/总结 | 单选/多选（概念辨析） | — | — |
| 应用 | 演示/应用 | 场景化单选 | 写出查询（结果正确） | — |
| 分析 | 分析/比较/检查 | 多选（因果/影响） | 多表/聚合/排查类 | 定位根因 |
| 评估 | 评估/评价 | — | 方案对比 | 选择处置方案并论证 |
| 创造 | 设计/开发 | — | — | 搭建/重构产线（沙盒） |

### 4.2 每主题内容配比（推荐）

| 单元 | 数量 | 开发工作量（个人经验估） |
|---|---|---|
| chapters（理论） | 4-8 章，每章 800-1500 字 MD | 每章 2-3 h |
| questions（测验） | 每章 3-4 题 + 模块考 8-10 题 | 每题 0.5 h |
| sql_exercises（SQL 实训） | 每主题 3-5 题（场景化题干 + 样例数据集 + answer_sql + answer_hash） | 每题 2-3 h |
| fault_scenarios（排障） | 每主题 1-2 个（L3 主题必配） | 每个 4-6 h |

### 4.3 章节模板（沿用现有风格，规范化）

```
# 章节标题
## 一句话理解        ← 核心概念一句话
## 结构/流程图       ← 代码块或表格（拒绝大段文字）
## 现场对应          ← 奥来/真实车间场景
## 观察任务          ← 可执行的小任务
## 常见坑 / 面试能讲  ← 面试话术素材
## 下一步            ← 章节链接
```

## 6. 开发路线图（P0 → P2，含工作量）

### P0 · 补验证闭环（先让已有内容可衡量）— 约 1.5 周

1. **主题 4-7 补测验**：每主题 6-8 题（ERP 7 题 / MES 8 题 / SQL 6 题 / PLC 6 题），覆盖记忆+理解+场景应用。→ 6-7 h/主题
2. **SQL 实训扩容 6 → 24 题**：新主题「SQL 面试实战」（子查询/窗口函数/日期/去重/分页/多表），对接 C3 数据能力。→ 36 h
3. **路线图去重**：rm-500 与 rm-502 合并或明确差异化（500=基础路径，502=泛行业实施方法论），rm-501 30 天冲刺保留，rm-503 个人定制保留。→ 2 h

### P1 · 排障与分析层（差异化核心）— 约 2-3 周

4. **fault_scenarios 首期 6 个场景**（每个含 prompt + solution_json + 积木容错规则）：
   - 工单状态卡死关不掉（C2/C6）
   - 报工数量与入库对不上（C3/C6）
   - 齐套检查虚判、现场领不到料（C3/C6）
   - 质量追溯断链：批次/SN 查不全（C3/C6）
   - 设备稼动率异常偏低（C4/C6）
   - 安灯呼叫不触发（C4/C6）
5. **主题「质量追溯与数据核查」完整课**（L3 样板课，见 §7 示例）：4 章 + 12 题 + 3 SQL + 2 场景。

### P2 · 认证与综合层 — 约 2 周

6. **certifications 种子数据** + 前端「我的证书」展示。
7. **沙盒课程化**：工艺路线搭建器配套任务卡（L4 创造层），场景取材奥来断路器真实工艺。
8. **L1 反馈问卷**：章节底部 2-3 题满意度（数据落 stats_daily 或独立表）。

## 7. 样板课设计示例：质量追溯与数据核查（L3）

> 可直接作为 P1 开发时的「第一个完整样本」，验证规范后批量复制。

### 7.1 ABCD 目标

- 给定追溯断链的批次数据(C)，学员(A)能通过 SQL 沿「成品 SN → 批次 → 工序报工 → 物料批次」链路逐层定位断点(B)，并输出断链原因与处置建议(D：正确指出断链层级，处置建议含 3 要素：影响范围/根因/预防)。
- 给定一批不良品(B)，学员能倒查涉事工单、物料批次与设备(D：追溯结果与标准答案一致)。

### 7.2 章节大纲（4 章，每章 1000 字内）

| 章 | 标题 | 布鲁姆 | 要点 |
|---|---|---|---|
| 1 | 追溯模型：正查与反查 | 理解 | 正向追溯（料→品）/反向追溯（品→料）、批次/SN 双轨 |
| 2 | 追溯链路的数据表支撑 | 应用 | 报工表/批次表/SN 表/物料表关联关系，断链常见位置 |
| 3 | 断链定位排查法 | 分析 | 逐层 COUNT 对比法、断点判定标准（数据缺失 vs 业务未录） |
| 4 | 追溯报告与整改 | 评估 | 影响范围评估、根因归类（人为/系统/流程）、预防措施 |

### 7.3 样例题（节选）

- **单选（理解）**：正向追溯与反向追溯的分水岭是？A. 工单号 B. 产品 SN/批次 C. 设备编号 D. 班组 —— 答案 B
- **多选（分析）**：某成品 SN 反查不到原料批次，可能原因？（3 项）—— 原料未做批次绑定 / 报工未录批次 / 原料批次已报废出库 / 查询用了错误的表关联
- **SQL 实训（分析）**：给定 3 表（报工表/批次表/SN 表），查出「追溯断链」的 SN 列表 —— 用 LEFT JOIN + IS NULL 定位缺失层级
- **排障场景（评估）**：质检发现 3 台断路器追溯缺失，给出排查路径 + 处置方案评分标准（按断链层级命中/措施完整性打分）

### 7.4 完成标志（柯氏 L3 前置）

学员能独立完成「从不良 SN 反查到原料批次与设备」的全链路 SQL，并在沙盘场景中按规范提交追溯报告。
