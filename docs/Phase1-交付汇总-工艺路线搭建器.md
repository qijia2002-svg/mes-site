## 2. 产品侧：把「看不懂的 MES 术语」变成「摸得着的积木」

PM 定的核心原则：**每个概念必须能落成画布上一个看得见、摸得着、可操作的东西。教不动手的概念一律砍掉。**

### 概念 → 可动手单元

| MES 概念 | 在画布上是什么 | 你的动作 |
|---|---|---|
| 工序 Operation | 可拖拽的工序块（名称 + 标准工时 + 质检标记） | 从左侧面板拖进画布 |
| 工艺路线 Routing | 工序块之间的连线构成的有序单链 | 拖连线串起来，可插入/删除/调序 |
| BOM 物料清单 | 挂在首道工序上的物料槽位（要什么/要多少/有多少） | 在属性面板配物料、调库存 |
| 工单 Work Order | 运行后沿路线流动的流转卡片 | 点运行，看卡片逐工序推进 |
| 报工 Report | 工序块上的产出计数器（合格/不良/报废三栏） | 单步模式手动填报工数 |
| 质检 QC | 工序块上的质检开关 + 运行时判定节点 | 开关质检，看下游是否被卡住 |

### 六个关卡 ↔ 六条铁律，一一映射

| 关卡 | 学会什么 | 触发的业务铁律 |
|---|---|---|
| L1 串起第一条线 | 工艺路线是有序序列 | R6 不能成环 |
| L2 跑起第一张工单 | 工单按工序串联，数量不拆分 | R2 |
| L3 开不了工 | 投料前置与工单冻结 | R1 齐套性 |
| L4 卡在质检口 | 质检是独立卡点，与报工分离 | R3 |
| L5 做了 1000 只认 970 | 只有合格数计入订单 | R4 完工口径 |
| L6 不良品去哪了 | 不良三岔口与独立返工工单 | R5 |
| 自由模式 | 自己设计路线并解释每个卡点 | 全部 |

> PM 特别标注：**L1-L6 引导关卡（F7）的 RICE 分只有 4.80，但不接受降级。** RICE 会系统性低估「防御性差异化」功能——砍掉它，产品就退化成「又一个流程图工具」，正好掉进 Scratch 被批评的坑（无结构化路径，自学者无从下手）。

### 功能清单

**模块 A 搭建器（P0）**：F1 工序块面板（数据驱动，不硬编码）· F2 画布拖拽连线（含实时合法性校验）· F3 工序属性面板 · F4 运行仿真与流转动画（单步/连续/暂停/重置）· F5 异常注入与业务解释卡 · F6 通用离散示例数据 · F7 引导关卡 L1-L6 · F8 方案保存与重置

## 3. 架构侧：零新增运行时依赖

架构师做了实测审计（不是推测），10 条结论里最关键的四条：

| 决策 | 结论 | 为什么 |
|---|---|---|
| **画布渲染** | 原生 Canvas 2D + DOM 叠加，**不引 React Flow / Konva / zustand** | 拖拽/连线/校验都是可控代码量；引库反而要跟它的抽象打架 |
| **仿真在哪跑** | **全部在前端** | Workers 免费版 10ms CPU/调用，逐 tick 仿真根本跑不动。后端只下发素材、只收结果摘要 |
| **仿真状态** | 放 **React 之外的可变引擎实例**，≤4Hz 节流推快照给 React | 高频 tick 走 setState 必卡；换状态库解决不了这个问题 |
| **异常注入** | 复用现有 `fault_scenarios` 表，**零 DDL 变更**，新增 `variant='sim'` | 表已经预留好了，多解容错用现成的 `block_solutions` |

**新增 5 张 `sim_` 前缀表**（`sim_scenarios` / `sim_operations` / `sim_process_routes` / `sim_work_orders` / `sim_bom_items`）。

两条架构师特意标注「实现时不要顺手优化掉」的约束：
1. **表名一律 `sim_` 前缀**——`work_orders` / `bom` 已被 sql.js 沙箱样例库占用（`web/src/features/sql-sandbox/dataset.sql:47,80`），同名不同结构会造成教学混淆。
2. **比率/单位用量一律整数定点（万分比 / ×1000），禁 REAL**——浮点在跨设备重放仿真时产生位级差异，学员会问「我照做了为什么结果不一样」。

**10 个新端点**：4 个学员侧（`/sim/scenarios`、`/sim/scenarios/{slug}`、`/sim/scenarios/{slug}/faults`、`POST /sim/runs`）+ 3 个管理侧场景 CRUD + 3 个导入三阶段（`preview` / `commit` / `finalize`）。

**路由级懒加载**：`React.lazy` + Suspense 放在 `AppShell` 内、`Routes` 外，**必须配 chunk-load ErrorBoundary**，hover 预热。不迁 TanStack Router——懒加载是 React 的能力不是路由库的，用 30 行类型化路径常量表拿 80% 的类型安全，零迁移成本。

## 4. 设计侧：Scratch 借三条、扔四条

设计师的对标结论——**借**：形状即语法（不合法的块根本插不进去）、拖拽即时物理反馈、运行态高亮当前执行块；**扔**：饱和度过高的儿童配色、圆润卡通描边、密集图标工具栏、无层级的无限画布。

关键规格：
- **9 态拖拽反馈矩阵**：idle / hover / grabbing / valid-target / invalid-target / snapping / dropped / selected / error，每态都有明确的视觉定义
- **运行态动效**：900ms 位移 + 600ms 驻留；`prefers-reduced-motion` 用 JS 检测降级为瞬时跳转（不是简单关动画，否则用户看不出发生了什么）
- **移动端 <768px**：画布降级为**纵向步骤列表**（不硬塞缩放画布，触屏拖拽连线体验必崩）
- **无障碍**：拖拽有完整键盘通路 + 读屏播报，不是「鼠标专属功能」
- **零新增 hex**：全部走既有 design-tokens

导入页是 **六态两步确认**：待导入 → 拖悬停 → 扫描中 → **预览确认（唯一写库闸门）** → 导入中 → 完成 / 部分失败（逐行冲突可单独处理）。
