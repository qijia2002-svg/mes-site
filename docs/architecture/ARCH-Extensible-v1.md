# ARCH-Extensible-v1 — 可扩展系统架构总纲

> 作者：Software Architect（架构师专家）
> 日期：2026-08-13
> 上游约束：《后端架构方案 v1》《DESIGN.md》《OPEN-DECISIONS.md》《ManufacturingOS-产品说明与路线图.md》及 ADR-001~ADR-023
> 状态：Proposed（待用户拍板后升格为 Accepted）
> 适用：MES 实训平台从「MVP 学习站」演进为「Manufacturing OS 交互式制造业学习平台」的中长期架构基线

---

## 0. TL;DR（一句话给决策者）

**本系统的"可扩展"不靠拆微服务，而靠"模块化单体 + 岛屿(Island)扩展契约 + 内容即数据 + 触发式毕业"。**
代码组织只要守住边界，规模增长由"加岛屿 / 加数据 / 加桥接"承载；只有当**量化触发器**（D1 写入吞吐、DO 告警、subrequest 限额、p99 延迟、团队规模）被击穿时，才把某个已解耦的岛屿**单独抽出成 Worker**——而这一步之所以无痛，正是因为岛屿从第一天起就是边界清晰的。

这与既有 ADR 完全一致：ADR 系列早已明确"免费套餐 + 单人项目下，消息队列 / CQRS / 多区域 / 服务拆分是负资产"。本总纲不是推翻它，而是把"未来万一要拆"的路预先铺好，让今天的单体不欠技术债。

## 1. 约束与现状盘点（设计必须先在地面上）

### 1.1 硬约束（不可妥协）

| 约束 | 来源 | 对架构的含义 |
|---|---|---|
| 单人维护 + 免费 Cloudflare 套餐 | README / ADR-001 | 运维面必须极小；不能引入自管中间件、不能依赖付费层才成立的能力 |
| D1 单库、单写线程、容量受限 | wrangler.toml 注释 / README | **写吞吐是真实天花板，不是代码组织问题**；读走 Cache API、写走批量/幂等、仿真态留客户端 |
| 中国大陆多通道可达性 | wrangler.toml 多自定义域注释 | 架构不依赖单一域名；前端可独立 CDN/域名，后端可多入口 |
| P0 视觉五红线（无 emoji / 无紫粉渐变 / 无裸 hex / 无弹跳 / 无千篇一律 Hero） | DESIGN.md | 设计系统即架构边界的一部分，组件须 token 化 |
| SKILL.md 为单一事实来源 | 团队规范 | 任何代码生成前先读规范，架构决策落 ADR 而非口头 |

### 1.2 现状（已落地的真实模块，非 README 旧描述）

**后端 `worker/src/modules/`**：`admin` `ai` `auth` `certifications` `content` `dict` `engine` `flowchart` `health` `knowledge` `learn`
**后端 `worker/src/data/repositories/`**：`admin` `cert` `chapter` `dict` `flowchart` `lp` `progress` `quiz` `roadmap` `userdata` `knowledge`
**前端 `web/src/features/`**：`factory`（工厂全景可视化）`factory-sim`（仿真沙盒岛）`glossary`（术语）`knowledge`（知识图谱）`roadmap`（职业路径）`sql-sandbox`（SQL 工作台）
**前端 `web/src/pages/`**：`Admin` `Career` `Chapter` `CourseDetail` `Courses` `Dictionary` `Exercise` `Factory` `LearningPaths` `Login` `Portfolio` `Profile` `Quiz` `QuizQuestion` `SqlSpace` `Tools` `TrackDetail`

> 结论：平台已从"内容+SQL"扩展为 **11 模块 / 6 前端岛**。**岛屿(Island)模式已经自发涌现**（`factory/`、`factory-sim/` 各自聚合数据+组件+路由），本总纲将其**正式化为契约**，而非另起炉灶。

### 1.3 已识别的扩展性风险（不解决会烂）

1. **模块间隐性耦合**：11 个模块直接共享 `DbSession` 与 `repositories/`，新岛若随手加跨库 JOIN，会破坏"岛屿自治"。
2. **内容≠数据**：25/33 课程无练习题、147 章仅 37 章有题（内容体检报告）。若每门新课都写新模块，扩展成本随课程数线性爆炸。
3. **跨岛桥接无契约**：sim↔sql 已有 `simToSql` 雏形，但若每次都临时耦合，仿真岛与 SQL 岛会锁死。
4. **迁移文件命名漂移**：`schema-*.sql` 与 `migration-*.sql` 混用，缺"每岛拥有自己 schema"的归属感，未来拆库时难以切割。
5. **单 D1 写线程天花板**：所有写（进度/仿真态/账号同步/统计）挤同一写线程，账户云同步（ADR-023）上线后会显著加压。

## 2. 领域边界 / Bounded Context Map

把现有 11 模块 + 6 岛归并为 **7 个界限上下文（Bounded Context）**，每个上下文内部高内聚、跨上下文只通过明确定义的点交互。

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         MES 实训平台 · 界限上下文地图                        │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                            │
│  [A] 课程与内容 Curriculum    [B] 测评与实训 Assessment    [C] 仿真 Sim     │
│   content/learn/knowledge    quiz/sql-sandbox/exercises     factory-sim    │
│   chapters/topics/lp/cert    ai-judge                        (Do 王牌)     │
│   roadmap/dict/glossary                                                    │
│        │                        │                            │             │
│        └───────────┬────────────┴─────────────┬────────────┘             │
│                    │      [D] 工厂可视化 FactoryViz                        │
│                    │       factory/ (Flow 全景, 非沙盒)                    │
│                    │                                                         │
│  [E] 身份与同步 Identity   ── 被 A/B/C/D 依赖（进度/收藏/错题/笔记）        │
│   auth/userdata/progress  (ADR-023 账号云同步, per-field LWW)               │
│                                                                            │
│  [F] 语义层 Semantic        ── 被 A/D 依赖（术语/知识图谱/关联推荐）         │
│   glossary/knowledge-graph                                                 │
│                                                                            │
│  [G] 平台与运维 Platform    ── 横切所有上下文                               │
│   admin/health/engine/ai/RateLimiter-DO/Cache/observability                │
│                                                                            │
└──────────────────────────────────────────────────────────────────────────┘
```

**上下文依赖方向（单向，禁止回环）**：
`[C 仿真] → [B 实训] → [A 课程]`（仿真可消费课程定义，反之不可）；`[D 可视化] → [A/F]`；`[E 身份]` 被所有人依赖但**不反向依赖任何人**；`[G 平台]` 被所有人依赖但不被依赖。
**反模式警示**：若 `content` 模块直接 `import quiz.repo` 去做"章节完成度统计"，就打破了 `[A]→[B]` 的单向，必须改为事件/桥接。

## 3. 可扩展架构设计（核心）

### 3.1 总体拓扑（C4 容器级）

```
┌──────────── 用户 ────────────┐         ┌──────── 内容作者 ────────┐
│ 零基础制造业转行新人 (Learner) │         │ Obsidian / Markdown 维护  │
└──────────────┬───────────────┘         └───────────┬───────────────┘
               │ HTTPS (多自定义域兜底)                 │ 同步管线(未来)
               ▼                                       ▼
┌──────────────────────────────────────────────────────────────────────┐
│                       Cloudflare Edge (单一 Worker 部署)                  │
│                                                                        │
│  ┌──────────────────────── 前端 SPA (React19+Vite) ─────────────────┐  │
│  │  AppShell / 路由懒加载 / feature 岛 (factory, factory-sim, ...)   │  │
│  └───────────────────────────────┬──────────────────────────────────┘  │
│                                   │ /api/v1/* (同源, 无跨域)              │
│                                   ▼                                      │
│  ┌──────────────────── 后端 Worker (模块化单体) ────────────────────┐   │
│  │  洋葱管道: trace→security→auth→ratelimit→validate→handler        │   │
│  │  ┌────────┐ ┌────────┐ ┌──────┐ ┌──────┐ ┌────────┐ ┌────────┐  │   │
│  │  │ A 课程 │ │ B 实训 │ │C 仿真│ │D 可视│ │E 身份 │ │G 平台 │  │   │
│  │  └───┬────┘ └───┬────┘ └──┬───┘ └──┬───┘ └───┬────┘ └───┬────┘  │   │
│  │      └──────────┴────────┴───桥接──┴────────┘     │        │     │   │
│  └───────────────────────────┬───────────────────────┴────────┘     │
│                               ▼                                      │
│  ┌─────────┐   ┌──────────────┐   ┌──────────────────────────────┐  │
│  │  D1     │   │ Durable Obj  │   │  Cache API (L2 只读缓存)       │  │
│  │ (单库   │   │ RateLimiter  │   │  + Workers AI (ai-judge)       │  │
│  │  单写)  │   │ 令牌桶/锁    │   │                               │  │
│  └─────────┘   └──────────────┘   └──────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

> 关键：**单 Worker 部署形态不变**（ADR-010/013、wrangler 多域策略已锁定）。扩展性来自 Worker **内部**的边界，而非部署单元的数量。

### 3.2 模块化单体 + 岛屿(Island)扩展契约（ADR-024）

**岛屿(Island)定义**：一个自包含的"功能域"，聚合自己的 `路由 + 数据模型(迁移) + 仓储 + 组件 + 懒加载入口`。现有 `factory/`、`factory-sim/` 已是实例。

**新岛屿的接入成本必须收敛到"加一个文件夹 + 注册一处"**（复用既有 module registry 的"新增主题零后端改动"思路）。

岛屿契约（每个岛必须提供）：
```ts
// features/<island>/island.ts  —— 声明式注册，禁止在核心层写 if(islandX)
export interface IslandContract {
  id: string;                  // 唯一, 如 'factory-sim'
  routes: RouteConfig[];       // 该岛的前端路由 + 对应后端 /api/v1/<id>/...
  migrations: string[];        // 该岛拥有的迁移文件清单 (见 3.5)
  lazyEntry: () => Promise<...>; // 路由级懒加载入口 (640KB+ 仿真引擎不进首屏)
  dependsOn: IslandId[];       // 仅声明依赖, 不 import 实现 (走桥接, 见 3.4)
}
```
**反模式**：在 `core/pipeline.ts` 或 `App.tsx` 里写 `if (island === 'sim')` —— 这是把边界烧进内核，必须拒绝。

### 3.3 内容即数据（Content-as-Data，ADR-026）—— 最高杠杆

**论点**：本平台 90% 的"新功能"其实是"新课/新章节/新题/新工厂模型"，本质是**数据**，不是**代码**。把内容当代码写，扩展成本随课程数线性增长，必崩。

**机制**：
- 课程线（ERP / 生产模式 ETO·MTO·MTS / 离散 vs 流程）以 `topics`+`chapters`+`learning_paths` **种子数据**落地，渲染复用同一套 `ChapterPage`/`QuizDeck`/`SqlSandbox`。
- 新增一门课 = 一份 seed +（可选）一个 explainer 数据文件，**零新模块**。
- 配套一条"内容生产管线"：Obsidian/Markdown → 校验 → staging → commit（复用 admin 的 Excel 分片导入两阶段思路），让非工程师也能扩内容。

> 这直接回应内容体检报告：25/33 课无题的问题，靠"内容管线 + 题库数据"解决，而非写 25 个模块。

### 3.4 跨岛桥接协议（Bridge Protocol，ADR-025）—— 架构基石

**现状**：`simToSql.ts` 已把仿真结果与 SQL 实操打通（记忆确认）。这是平台"王牌差异化"的技术核心，但当前是临时耦合。

**契约化**：跨岛交互一律走**显式桥接接口**，禁止岛间直接 import 实现。

```
仿真岛(C) ──produce──> FactoryStateSnapshot ──consume──> SQL岛(B)
                         (标准 JSON Schema)             (注入为可查询数据集)
```
- `FactoryStateSnapshot` 是**版本化契约**（v1 先冻结字段：WIP/leadTimeMin/工序状态/物料流转），变更走 semver，向后兼容。
- 仿真岛只"产出快照"，不关心 SQL 岛怎么用；SQL 岛只"消费快照"，不关心仿真怎么算。
- 未来 `可视化岛(D)`、`知识图谱(F)` 也可消费同一快照，形成"一次仿真，多岛复用"。
- **降级**：若桥接失败，各岛独立可用（仿真仍可玩、SQL 仍可练），符合 ADR-018 软引导精神。

### 3.5 数据层扩展性：每岛独立迁移 + Schema 所有权（ADR-027）

D1 是**单库单写线程**，这是硬墙。应对不是"拆库"（免费套餐不可行），而是**严明的 schema 归属感**，让未来万一要拆 Worker 时能干净切走。

**规则**：
1. 每个岛屿拥有**自己的一组迁移文件**，命名 `migrations/<island>-vN.sql`（如 `factory-sim-v1.sql`、`knowledge-v1.sql`），废止 `schema-*.sql` 与 `migration-*.sql` 混用。
2. 跨岛查询只允许通过**仓储层**与**桥接快照**，禁止跨岛 `JOIN` 原始表（否则拆库时断裂）。
3. 读路径统一过 `Cache API`（已有 L2 缓存 + 单飞），写路径走 `DbSession` 预算守卫（已有 40 条/请求红线）。
4. **统计聚合**走写时聚合（`stats_daily`），不在请求期算。

> D1 写线程天花板是真实瓶颈：账户云同步（ADR-023）上线后，进度/笔记/收藏/错题的写会叠加。缓解 = 客户端批量 + 幂等 + 异步落库（复用 progress 既有幂等写入），并把"非实时"写（统计、学习轨迹）降级为后台聚合。

### 3.6 前端扩展：路由级懒加载 + feature 岛（已部分落地）

- 每个岛屿 `lazyEntry` 路由级 `React.lazy` + `Suspense`（仿真引擎 640KB+ 不进首屏，ADR-009 已定）。
- `AppShell` 只认 `IslandContract[]`，不认具体岛 —— 加岛不改 shell。
- 设计系统（token/CSS）是跨岛的**唯一共享**，岛屿不得引入私有配色/字体（P0 红线）。

### 3.7 身份与同步（承接 ADR-023）

- 已拍板：邮箱+密码、强制注册、云同步进度/笔记/收藏/错题、per-field LWW。
- 架构含义：身份上下文 `[E]` 是**所有岛的依赖根**，必须最稳定、最少依赖。同步冲突用 per-field LWW，避免全局锁。
- 客户端 `userData` 层（已有 `lib/userData.ts`/`profileStore.ts`/`portfolioStore.ts`）承担离线优先 + 异步上行的职责，与 ADR-007"仿真态可导出导入 JSON"一致。

## 4. 长期演进路线（Phase + 触发门禁）

**核心思想**：阶段由**触发器**驱动，而非拍脑袋排期。每个阶段结束都有"可验证的门禁"，达到才进下阶段。

### Phase A — 固本（现在 → ~3 个月）：把单体边界钉死
**目标**：落地岛屿契约、内容即数据、桥接协议；补齐 P0 仿真沙盒、ERP/生产模式课程线、Obsidian 同步、账户云同步。
**交付**：
- ADR-024~028 升格 Accepted，全仓库执行岛屿契约。
- 仿真沙盒（P0）按桥接协议与 SQL 岛打通（王牌落地）。
- 内容管线：Obsidian/Markdown → staging → commit；ERP/生产模式课程线 seed。
- 账户云同步（ADR-023）落地 + 写路径批量/幂等改造。
**门禁**：新加一个"课程线"或"前端岛"的改动量 ≤ 1 文件夹 + 1 注册处；D1 写 p99 < 200ms。

### Phase B — 规模（3 → 9 个月）：内容海量与多模型
**目标**：知识图谱成熟、多工厂模型切换（阀门/电机/电器装配）、作品集、AI 判读自由理解扩面。
**交付**：
- 仿真岛支持多工厂模型（v2 快照契约扩展，向后兼容）。
- 内容管线自动化（CI 校验 seed 结构 + 判题哈希回归，复用现有 CI）。
- 读路径缓存命中率优化（预热 + 边缘缓存策略）。
**门禁**：日活写请求接近 D1 单写线程预警线（见触发器 T1）；缓存命中率 ≥ 85%。

### Phase C — 毕业（9 → 18+ 个月）：按需拆 Worker（不重写）
**目标**：当某岛屿触发量化阈值，将其**单独抽出成独立 Worker / 子域**，其余保持单体。
**交付**：
- 因边界早已清晰，抽出 = 把该岛的 `routes+migrations+repositories` 移到新 Worker，桥接协议不变（仅 transport 从进程内调用变 HTTP）。
- 典型首批候选：① `ai-judge`（调用 Workers AI，易独立、省主 Worker 算力）；② 内容/CDN 只读 Worker（高缓存命中、可独立扩边缘）。
**门禁**：触发 T2~T5 任一即启动对应岛屿的抽取评估。

### 触发器表（量化决策依据）

| ID | 触发器 | 阈值（示例，实施前以实测校准） | 动作 |
|---|---|---|---|
| T1 | D1 单写线程饱和 | 写 p99 > 300ms 或写错误率 > 1% 持续 7 天 | 写路径再批量化 + 评估只读副本/拆分写岛 |
| T2 | DO 限流告警频发 | 合法用户被令牌桶误伤率 > 0.5% | 调整桶参数，或把 ai-judge 拆出减负 |
| T3 | subrequest / CPU 触顶 | 单请求接近 50 subrequest 或 CPU 软限告警 | 拆出重算力岛屿（ai/sim 后端） |
| T4 | 团队规模 | 维护者 > 3 人且并行改同一单体冲突频繁 | 按岛屿分 repo/分责，启动抽取 |
| T5 | 中国可达性 | 某入口域持续不可达 | 增备入口域（沿用 wrangler 多域策略） |

> 重要：触发器是"必要条件非充分"。抽 Worker 前必须先在 Phase A/B 把边界钉死——**否则今天偷懒的耦合，就是明天拆不动的债**。

## 5. 关键决策与权衡（架构师必须点名放弃了什么）

| 决策 | 得到 | 放弃 | 为什么值得 |
|---|---|---|---|
| 模块化单体 + 岛屿契约（非微服务） | 极低运维、单人可维护、免费套餐可行 | 独立部署/独立扩缩、技术异构 | 当前规模下微服务是负资产（ADR 已证） |
| 内容即数据 | 课程扩展成本趋零 | 极致定制化的"每课一套 UI" | 90% 新需求是内容，统一渲染够用 |
| 桥接协议而非直接耦合 | 岛可独立演进/降级 | 一次性开发略慢、需定义契约 | 这是王牌差异化的技术护城河 |
| 单 D1 + 严明 schema 归属 | 免费可行、零运维 | 水平写扩展（直到 T1 触发） | 免费套餐唯一选择，用边界换未来可拆 |
| 触发式毕业（非预设拆分） | 不为未发生的规模付费 | "看起来先进"的架构 | 避免架构宇航员病 |

**被挑战的假设**：用户提到"大型软件系统需要整体架构"。常见直觉是"大=微服务"。本设计**明确反对**在当前约束下上微服务，并用触发器证明：可扩展性来自**边界**，不来自**部署单元数量**。

## 6. 新 ADR 登记（详见 docs/decisions/ADR-024~028）

- **ADR-024** 模块化单体 + 岛屿(Island)扩展契约 — 新域接入收敛到"1 文件夹 + 1 注册处"
- **ADR-025** 跨岛桥接协议 — sim/sql/content 经版本化 `FactoryStateSnapshot` 解耦
- **ADR-026** 内容即数据 — 新课/新厂模型=种子数据+渲染器，零新模块
- **ADR-027** 每岛独立迁移 + Schema 所有权 — 废止 schema-/migration- 混用，禁跨岛 JOIN
- **ADR-028** 单体毕业触发器 — T1~T5 量化门禁驱动按需抽 Worker，不重写

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单人维护，边界靠自觉 | 耦合回潮 | CI 静态检查岛屿依赖方向；新 PR 必须声明岛屿归属 |

| 桥接契约定义过早/过晚 | 要么过度设计要么锁死 | v1 先冻结最小字段，semver 演进，向后兼容 |
| Obsidian 同步管线复杂度 | 偏离核心（仿真） | P1 排期，沙盒(P0)先行（路线图已定） |
| 免费套餐限额变动 | 触发器阈值漂移 | 实施前实测校准阈值，文档标注"示例值" |
