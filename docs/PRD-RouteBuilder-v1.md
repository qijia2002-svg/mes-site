## 1. 问题陈述

### 1.1 谁，在什么场景下，遇到什么痛点

零基础想转行做 ERP/MES 实施的人，以及制造业里被临时指派去对接信息化项目的专员，在**入门期的前 3-6 个月**卡在同一个地方：

**他们能背出术语，但不知道这些术语之间怎么串起来。**

调研中反复出现的原话（来源见 §3 竞品与调研）：

- 「术语晦涩」——大量专有名词和缩写，工艺路线 / 工序 / 工单 / BOM / 报工 / 齐套，字面都认识，合起来不知道在讲什么。
- 「理论难以实践，纸上谈兵难以理解实际流程」。
- 「不知道怎么搭建典型场景」——看完教程，面对空白系统依然无从下手。
- 「参数太多不会设」。
- 典型卡点提问：**「为什么库存足够却无法出库」**——这类问题本质是跨模块协同规则不理解，而不是操作不会点。

行业公认的时间成本：跨模块协同理解需要 **3-6 个月**；无计划自学达到初级水平需要 **6 个月以上**，系统化训练可压缩到 **3 个月**。

### 1.2 现在怎么解决的，为什么不行

| 现有解法 | 为什么不行 |
|---|---|
| 看文档 / 视频课 | 单向输入，学完仍然「搭不出场景」。我们平台当前也停在这一层。 |
| 厂商试用系统（用友 / 金蝶试用版） | 界面是给熟手设计的，几十个模块上百个功能点，没有教学引导，新手点开就劝退；还要装环境。 |
| ERP 沙盘（手工 / 电子） | 见 §3。核心问题是它教的是**经营决策**，恰恰把**生产执行**这一层自动化掉了。 |
| 写 SQL 练表结构（平台现状） | 能练查询，但表与表之间的**业务约束**（先投料才能开工、上道没质检合格下道不能干）SQL 题面表达不出来。 |

### 1.3 一句话结论

> 新手缺的不是「知识点讲解」，是一个**能亲手把工序拼起来、按下运行、看着工单流转、拼错立刻被拦下并被告知为什么**的地方。

## 3. 竞品分析

### 3.1 参考母版：Scratch / TurboWarp（跨行业方法论借鉴）

Scratch 的设计哲学是 **低门槛 / 高天花板 / 宽墙壁**（Low Floor / High Ceiling / Wide Walls），核心机制有三条值得直接搬到工业教学：

1. **形状即语法约束**——积木的凹凸形状决定了它只能以合法方式拼接，从物理上消灭语法错误。
   → 本土化：**工序块的连接点决定它只能接在合法的上下游位置**，路线拼错在「连线时」就被拦，而不是等到运行时才报错。
2. **即时运行反馈**——拖完点绿旗立刻跑，改一块立刻看到变化。
   → 本土化：改工序顺序 / 改「是否需质检」开关后，**重新运行立刻看到工单流转结果变化**。
3. **可容忍的凌乱**——允许把没用上的块先扔在画布旁边，鼓励试错而非先规划。
   → 本土化：画布允许存在未接入路线的游离工序块，不阻断运行，只做弱提示。

**Scratch 被实证批评的两点，正是我们的机会：**

| Scratch 的短板（有据可查的评价） | 我们的对策 |
|---|---|
| 「缺乏结构化、渐进的课程编排，自学者没有通往精通的清晰路径」 | 搭建器内置**引导式关卡**（见 F7），从 3 道工序的直线路线起步逐级加约束 |
| 「对低效方案不给针对性反馈，学生可能无意中固化坏习惯」 | 每次运行失败都返回**业务解释**而非仅报错码；把 MES 现场铁律做成显式规则（见 §4.2） |

> TurboWarp 的价值在于证明了「同一套积木内核可以被改造、扩展、跑得更快」——对我们的启示是**工序块的类型表应当数据驱动、可扩展**，为后续换成奥来电器断路器真实流程留接口。

| 竞品 | 核心功能 | 优势 | 劣势（来自公开评价与教研文献） | 定价 |

| 替代方案 | 优势 | 劣势 |
|---|---|---|
| B 站 / 慕课 视频教程 + 公众号长文 | 免费、量大、随时看 | 纯单向；「纸上谈兵」；看完仍搭不出场景 |

### 3.4 关键差评归纳（差评暴露的市场空白）

把上面所有竞品的短板叠起来，露出一块**没人占的位置**：

> 一个**单人可用、浏览器直接打开、不需要老师、聚焦生产执行层、拼错会被拦下并解释原因、可以无限次重来**的动手工具。

- 沙盘类：聚焦经营决策，**主动省略生产执行** → 空白。
- 厂商系统：有生产执行，**但没有教学引导和纠错解释** → 空白。
- 低代码平台：有拖拽体验，**但没有行业规则** → 空白。
- Scratch 类：有拖拽哲学和即时反馈，**但没有领域内容和渐进课程** → 空白。

## 4. 我们的差异化

### 4.1 定位一句话

**把「离散制造生产执行的业务铁律」做成可拖拽、可运行、拼错会解释原因的积木——单人在浏览器里就能反复试错。**

### 4.2 差异化的技术性内核：六条「可教铁律」

这是本产品区别于「又一个流程图工具」的关键。搭建器不是画图工具，它是一台**规则引擎**。以下六条规则来自离散制造 MES 的真实约束，每一条违反都对应一个可视化的报错和一段业务解释：

| 编号 | 铁律 | 违反时的教学价值 |
|---|---|---|
| **R1 投料前置** | 首道工序必须先完成投料才允许开工；物料未齐套的工单自动「冻结」 | 回答了新手最常问的「为什么库存足够却无法出库/开工」 |
| **R2 禁止跳序** | 非首道工序报工时，上道工序必须已有产出 | 建立「工艺路线是有序序列，不是任务清单」的认知 |
| **R3 质检卡点** | 工艺路线上标记「需质检」的工序，必须质检合格后下道工序才可继续 | 区分「报工」与「质检」是两件事——新手最容易混为一谈 |
| **R4 完工口径** | 只有末道工序质检合格的数量，才计入订单完成数量 | 解释「做了 1000 件为什么系统只认 970 件」 |
| **R5 不良三岔口** | 不合格品处置只能三选一：改判合格 / 报废 / 返工；返工生成**独立的返工工单**，走独立的下达-报工-质检流程 | 建立质量闭环概念，纠正「返工就是数量减一下」的误解 |
| **R6 路线合法性** | 工艺路线必须是有向无环的单链，不得成环、不得断链、不得存在孤立首尾 | 在「连线时」就阻止非法结构，对应 Scratch 的形状约束 |

> **重要认知纠偏**（新手第一大误区，必须在产品里显式教掉）：
> 投产 1000 件、工艺为「下料 → 机加工 → 焊接」3 道工序，审核后产生的是 **3 张工单，每张数量都是 1000**（按工序串联），**不是**把 1000 件分成三份。这个误解如果不打掉，后面所有排产和报工逻辑都会理解错。

### 4.3 与自身现有能力的协同

| 已有资产 | 在本阶段如何复用 |
|---|---|
| `fault_scenarios` 表（含 `variant: factory\|blocks`） | 直接作为搭建器的关卡/异常场景载体，无需新建表族 |
| `block_solutions` 表（`rule_json`） | 直接作为六条铁律的规则配置载体 |

## 5. 最小可教概念集

设计原则：**每个概念必须能落成画布上一个看得见、摸得着、可操作的东西**。教不动手的概念一律砍掉。

### 5.1 概念 → 可动手单元 映射表

| 概念 | 在画布上是什么 | 用户的动手动作 | 学会的判据 |
|---|---|---|---|
| **工序 Operation** | 一个可拖拽的**工序块**，块上显示工序名 + 标准工时 + 质检标记 | 从左侧块面板拖到画布 | 能说出工序是「一次加工动作」，不是「一个部门」 |
| **工艺路线 Routing** | 工序块之间的**连线**构成的有序单链 | 拖拽连线把工序串起来，可插入 / 删除 / 调序 | 能独立搭出「下料→机加工→焊接→质检→装配」并解释为何不能颠倒 |
| **BOM（物料清单）** | 挂在**首道工序**上的物料槽位，显示「需要什么、需要多少、当前有多少」 | 在首道工序的属性面板里配物料，或直接调库存参数 | 能解释齐套性检查是什么，缺料为什么开不了工 |
| **工单 Work Order** | 运行后沿路线流动的**流转卡片**，卡片上有工单号 / 数量 / 当前状态 | 点「运行」，观察卡片逐工序推进 | 能说出「3 道工序 = 3 张工单，每张都是 1000 件」 |
| **报工 Report** | 工序块上的**产出计数器**（合格 / 不良 / 报废三栏） | 在单步模式下手动填报工数量，或让仿真自动跑 | 能区分报工三种类型对工单和订单统计的不同影响 |
| **质检 QC** | 工序块上的**质检开关** + 运行时的合格/不合格判定节点 | 打开/关闭某工序的质检要求，观察下游是否被卡住 | 能解释报工与质检是分离的两个动作 |

### 5.2 概念引入顺序（渐进式脚手架，补 Scratch 之缺）

| 关卡 | 引入概念 | 路线复杂度 | 触发的铁律 | 学习目标 |
|---|---|---|---|---|
| **L1 串起第一条线** | 工序、工艺路线 | 3 道工序，直线 | R6 | 知道工艺路线是有序序列 |
| **L2 跑起第一张工单** | 工单、流转 | 3 道工序 | R2 | 知道工单按工序串联，数量不拆分 |
| **L3 开不了工** | BOM、齐套性 | 3 道工序 + 缺料注入 | R1 | 理解投料前置与工单冻结 |
| **L4 卡在质检口** | 质检、报工分离 | 4 道工序，中间设质检 | R3 | 理解质检是独立卡点 |
| **L5 做了 1000 只认 970** | 报工三类型、完工口径 | 5 道工序，末道质检 | R4 | 理解合格数才计入订单 |
| **L6 不良品去哪了** | 返工工单、质量闭环 | 5 道工序 + 不良注入 | R5 | 理解不良三岔口与独立返工工单 |
| **自由模式** | 全部 | 不限 | 全部 | 自己设计路线并解释每个卡点 |

> 六个关卡对应六条铁律，一一映射，不多不少。这套编排本身就是 Scratch 缺失的那条「通往精通的清晰路径」。

## 6. 核心功能清单

### 6.1 模块 A：工艺路线搭建器（本阶段 P0）

| 编号 | 功能 | 说明 |
|---|---|---|
| **F1** | 工序块面板 | 左侧列出可用工序块类型（下料 / 机加工 / 焊接 / 质检 / 装配 / 包装等），块类型**数据驱动**，来自后端配置而非硬编码，为后续换真实流程留口 |
| **F2** | 画布拖拽与连线 | 拖块入画布、拖拽移动、连线成链、删除块/连线；连线时实时校验 R6，非法连接在松手前就给出拒绝反馈 |
| **F3** | 工序属性面板 | 配置工序名、标准工时、是否需质检、首道工序的物料需求（BOM 槽位） |
| **F4** | 运行仿真与流转动画 | 点「运行」，工单卡片沿路线逐工序推进，工序块显示当前在制数量与产出计数；支持**单步 / 连续 / 暂停 / 重置** |
| **F5** | 异常注入与业务解释 | 场景可预置或手动注入缺料 / 质检不合格等异常；触发时对应工序块标红、流转停住，并弹出**业务解释卡**（这是什么规则 / 为什么现实中要这样 / 怎么解决） |
| **F6** | 通用离散制造示例数据集 | 首期素材：简化的工序库、工单、BOM，把交互跑通 |
| **F7** | 引导式关卡（L1-L6） | 按 §5.2 编排的六关 + 自由模式；每关有目标描述、通关判定、完成后写入进度 |
| **F8** | 方案保存与重置 | 保存当前画布方案、载入、重置为关卡初始状态 |

### 6.2 模块 B：Markdown 导入（本阶段 P1）

范围严格限定为**单向导入**：本地选 Markdown 文件 / 文件夹 → 解析 → 入库为 `topics` / `chapters`。

| 编号 | 功能 | 说明 |
|---|---|---|
| **F9** | 本地文件 / 文件夹选择 | 支持选单个 `.md` 文件，也支持选整个文件夹递归扫描；自动跳过 `.obsidian/`、隐藏目录、`node_modules` |
| **F10** | frontmatter 解析与字段映射 | 解析 YAML frontmatter，映射到 `topics` / `chapters` 字段（见 §6.3）；无 frontmatter 时按降级规则推断 |
| **F11** | 导入前预览（dry-run） | 展示「将新建 N 个 topic / M 个 chapter，将更新 X 条，将跳过 Y 条」的清单，用户确认后才真正写库 |
| **F12** | 导入结果报告 | 逐文件列出成功 / 跳过 / 失败及原因，失败项可单独重试 |

### 6.3 frontmatter 字段映射约定

```yaml
---
title: 工艺路线与工序               # → chapters.title（缺省时取正文首个 H1，再缺省取文件名）
topic: 生产执行基础                 # → topics.title，按 slug 匹配已有 topic，不存在则新建
topic_slug: production-execution   # → topics.slug（缺省时由 topic 转写生成）
sort: 20                           # → chapters.sort（缺省时按文件名自然序）
status: published                  # → chapters.status，取值 published | draft，缺省 draft
tags: [MES, 工单]                   # → tags / topic_tags
---
```

未识别的 frontmatter 字段：保留原值存入扩展字段，不阻断导入。

### 评分说明与例外

1. **F7 引导式关卡分数偏低但必须进 MVP。** RICE 会系统性低估「防御性差异化」功能。若砍掉 F7，产品退化成「又一个流程图工具」，正好落进 Scratch 被批评的坑（无结构化路径、自学者无从下手）。**这是差异化的锚点，不接受降级。**
2. **模块 B（F9-F12）Reach 只有 2，因为直接使用者只有内容作者（当前实质是 1 人）。** 但它是**内容供给的杠杆**——间接受益的是全部学习者。建议排期上放在模块 A 之后，作为同阶段的第二批次交付，而不是砍掉。
3. **Effort 合计约 25 人月为单人口径的粗估**，实际排期以架构师的技术方案为准，本表仅用于**相对优先级排序**，不作为工期承诺。

## 9. 验收标准（EARS）

> 格式：`While <状态> / When <事件> / If <异常> / Where <可选特性>` + `系统必须|应该` + 行为。
> 「必须」= 不满足即验收不通过；「应该」= 强烈建议，可作为已知缺口带条件通过。

### 9.1 模块 A — 画布与搭建（F1-F3）

| ID | 验收标准 |
|---|---|
| AC-A01 | 系统必须在搭建器左侧展示工序块面板，块类型列表由后端配置下发，前端不得硬编码工序名称。 |
| AC-A02 | When 用户从块面板拖动一个工序块并在画布区域释放，系统必须在释放位置创建该工序块实例，并使其立即处于可选中、可再拖拽状态。 |
| AC-A03 | When 用户从一个工序块的输出连接点拖向另一个工序块的输入连接点，系统必须在两者之间建立一条有向连线。 |
| AC-A04 | If 用户尝试建立的连线会导致路线成环，系统必须在鼠标释放前拒绝该连接，并以非阻断提示说明「工艺路线不能回到已经过的工序」。 |
| AC-A05 | If 用户尝试将一条连线接入某工序块已被占用的输入连接点，系统必须拒绝该连接并说明当前阶段工艺路线为单链结构。 |
| AC-A06 | When 用户选中一个工序块，系统必须展示属性面板，其中包含工序名称、标准工时、是否需质检开关；Where 该工序块为路线首道工序，属性面板还必须包含物料需求（BOM）配置区。 |
| AC-A07 | When 用户修改任一工序属性，系统必须即时更新画布上该块的可视状态，且不得要求用户手动保存后才生效。 |
| AC-A08 | While 画布上存在未接入主链路的游离工序块，系统必须以弱提示（非红色报错）标注这些块，且不得因此阻止用户点击运行。 |
| AC-A09 | 系统必须支持删除工序块与连线；When 用户删除链路中间的某个工序块，系统必须同时移除其关联连线，并保持剩余两段路线各自的完整性，不得自动跨接。 |
| AC-A10 | 系统所有功能图标必须取自 `Icon.tsx` 的语义名出口，不得使用 emoji 作为功能图标。工序块图标使用 `process`（里程碑形），工艺路线使用 `routing`（流程分叉形），工单使用 `work-order`（板夹清单形），报工使用 `report`（板夹对勾形），质检使用 `quality`（盾牌对勾形），物料使用 `material`（包裹形），BOM 使用 `bom`（多层方块形）。 |

### 9.2 模块 A — 运行与仿真（F4）

| ID | 验收标准 |
|---|---|
| AC-A11 | When 用户点击「运行」，系统必须生成一张工单，并使其从首道工序开始沿连线顺序推进，每次工序切换必须有可见的位移动画。 |
| AC-A12 | 系统必须为每道工序生成一张工序级工单，且每张工单的计划数量必须等于订单投产数量（例如投产 1000 件、3 道工序 → 3 张工单，每张 1000 件），不得将数量在工序间均分。 |
| AC-A13 | While 仿真运行中，系统必须在每个工序块上实时显示在制数量与产出计数（合格 / 不良 / 报废三栏）。 |
| AC-A14 | 系统必须提供单步、连续、暂停、重置四种运行控制；When 用户点击重置，系统必须将工单状态与所有计数清零，同时**保留**用户搭建的路线结构。 |
| AC-A15 | When 用户在仿真暂停或结束后修改路线结构或工序属性并再次点击运行，系统必须以修改后的配置重新执行，且不得残留上一次运行的状态数据。 |
| AC-A16 | While 用户系统偏好设置为减弱动态效果（`prefers-reduced-motion`），系统必须以状态跳变替代位移动画，且不得丢失任何流转步骤的可读信息。 |

### 9.3 模块 A — 六条铁律与异常反馈（F5）

| ID | 对应铁律 | 验收标准 |
|---|---|---|
| AC-A17 | R1 | If 首道工序的物料未齐套，系统必须阻止该工单开工，将工单状态置为「冻结」，将首道工序块标红，并展示业务解释卡说明齐套性检查的含义与现实原因。 |
| AC-A18 | R2 | If 用户在单步模式下尝试对非首道工序报工，而其上道工序尚无产出，系统必须拒绝该次报工，并说明工艺路线是有序序列、不允许跳序。 |
| AC-A19 | R3 | While 某道工序被标记为「需质检」且其质检结果尚未判定为合格，系统必须阻止下道工序开工，并在该工序块上显示质检卡点标识。 |
| AC-A20 | R4 | When 仿真运行结束，系统必须仅将末道工序质检合格的数量计入订单完成数量，并在结果面板中同时展示投产数量与完成数量的差额及其构成。 |
| AC-A21 | R5 | When 某道工序产生不良品，系统必须要求用户在「改判合格 / 报废 / 返工」三者中作出选择；If 用户选择返工，系统必须生成一张独立的返工工单，并使其走完独立的下达-报工-质检流程，不得直接在原工单上扣减数量。 |
| AC-A22 | R6 | If 用户在路线存在断链、成环或缺少首/末道工序的情况下点击运行，系统必须阻止运行并明确指出问题所在的具体位置。 |
| AC-A23 | — | When 任一铁律被触发，系统必须展示业务解释卡，且该卡片必须至少包含三段内容：触发了什么规则、现实工厂里为什么要有这条规则、当前场景下如何解决。 |
| AC-A24 | — | 业务解释卡的文案必须使用面向零基础读者的具体表述，不得出现空洞占位或模板化开场白。 |
| AC-A25 | — | If 用户已按解释卡的提示修正了配置（例如补齐物料）并再次运行，系统必须使该异常不再触发，让用户获得明确的修正闭环反馈。 |

### 9.4 模块 A — 关卡与进度（F7、F8）

| ID | 验收标准 |
|---|---|
| AC-A26 | 系统必须提供 L1 至 L6 六个引导关卡与一个自由模式；每个关卡必须包含目标描述、初始画布状态与通关判定条件。 |
| AC-A27 | When 用户满足某关卡的通关判定条件，系统必须即时给出通关反馈，并向 `progress_events` 写入一条完成事件，使其可被首页进度仪表盘统计。 |
| AC-A28 | 系统必须保证同一用户在同一自然日对同一关卡重复通关时不重复计数（沿用现有 `event_id` 幂等策略）。 |
| AC-A29 | While 用户处于某个引导关卡中，系统必须仅开放该关卡所需的工序块类型，避免新手被无关选项干扰；While 用户处于自由模式，系统必须开放全部工序块类型。 |
| AC-A30 | When 用户点击「保存方案」，系统必须持久化当前画布结构；When 用户重新进入搭建器，系统应该恢复其最近一次保存的方案。 |

### 9.5 模块 B — Markdown 导入（F9-F12）

| ID | 验收标准 |
|---|---|
| AC-B01 | 系统必须支持用户选择单个本地 `.md` 文件，也必须支持选择一个本地文件夹并递归扫描其中的 `.md` 文件。 |
| AC-B02 | While 递归扫描文件夹，系统必须跳过以点号开头的目录（含 `.obsidian/`）与 `node_modules`，且不得因跳过而中断整体扫描。 |
| AC-B03 | When 解析一个 Markdown 文件，系统必须提取位于文件开头、由一对 `---` 包裹的 YAML frontmatter，并按 §6.3 的约定映射到 `topics` / `chapters` 字段。 |
| AC-B04 | If 文件不含 frontmatter，系统必须降级推断：标题取正文首个 H1，若无 H1 则取文件名（去扩展名）；`status` 默认为 `draft`；`sort` 按文件名自然序。 |
| AC-B05 | If 某个文件的 frontmatter 为非法 YAML，系统必须跳过该文件的 frontmatter 解析并转入降级推断，同时在结果报告中标记为「已降级」，不得因单文件解析失败而中止整批导入。 |
| AC-B06 | When 用户确认导入源后，系统必须先展示 dry-run 预览，列出将新建、将更新、将跳过的条目数量与明细，且在用户显式确认前不得写入数据库。 |
| AC-B07 | If 待导入的 chapter 与库中已有记录标题与所属 topic 均相同，系统必须将其识别为「更新」而非「新建」，避免产生重复章节。 |
| AC-B08 | If frontmatter 指定的 `topic_slug` 在库中不存在，系统必须新建该 topic；If 已存在，系统必须复用，不得创建同名重复 topic。 |
| AC-B09 | When 导入执行完成，系统必须展示结果报告，逐文件列出成功 / 跳过 / 失败状态及失败原因，并允许对失败项单独重试。 |
| AC-B10 | When 导入成功写入任何内容，系统必须递增 `platform_config.content_version`，以确保内容缓存正确失效。 |
| AC-B11 | While 导入进行中，系统必须展示进度指示，并禁止用户重复提交同一批次导入。 |
| AC-B12 | Where 浏览器不支持目录选择能力，系统必须降级为多文件选择方式，并明确告知用户当前浏览器的能力限制，不得静默失败。 |
| AC-B13 | 系统必须将导入功能限定在管理端入口，普通学习者视图不得暴露该入口。 |
| AC-B14 | If Markdown 正文中包含 Obsidian 双链语法 `[[...]]`，系统必须将其按纯文本原样保留，不得渲染为失效链接，也不得因此报错。 |

## 10. 边界条件

| 类别 | 场景 | 期望行为 |
|---|---|---|
| 空状态 | 首次进入搭建器，画布为空 | 展示引导入口与「从 L1 开始」按钮，不展示空白画布无提示 |
| 空状态 | 导入源文件夹内没有任何 `.md` 文件 | 明确提示未发现可导入文件，并说明扫描规则 |
| 边界值 | 画布上工序块数量达到上限（建议 30） | 阻止继续添加并说明上限原因（教学场景不需要更长路线） |
| 边界值 | 工序标准工时输入 0 或负数 | 拒绝输入并给出取值范围提示 |
| 边界值 | 投产数量为 0 | 拒绝运行并提示投产数量必须为正整数 |
| 边界值 | 单个 Markdown 文件超过 1 MB | 跳过并在报告中标记原因 |
| 边界值 | 单次导入文件数超过 200 | 提示分批导入，不得整批失败 |
| 错误状态 | 仿真运行中出现未预期的引擎异常 | 停止仿真、保留画布结构、提供「重置仿真」而非整页崩溃 |
| 错误状态 | 保存方案时网络失败 | 保留本地画布状态，提示重试，不得丢失用户搭建成果 |
| 加载状态 | 搭建器模块首次加载（含仿真引擎） | 展示骨架屏或加载指示，主导航保持可用 |
| 离线 | 断网后继续搭建与运行 | 搭建与仿真为纯前端计算，必须可继续；仅保存与进度上报降级并提示 |
| 并发 | 用户在两个标签页分别保存方案 | 后写入者覆盖，并在下次载入时提示存在较新版本 |
| 权限 | 非管理员访问导入入口 | 返回无权限提示并引导回学习首页，不得暴露功能细节 |
| 兼容 | 移动端访问搭建器 | 本阶段提供只读查看与运行观看，不提供拖拽编辑，且必须显式告知 |

## 11. Out of Scope（本阶段明确不做）

以下项目均为**有意识的排除**，不是遗漏。任何一项进入本阶段范围都需要重新评审。

### 11.1 内容管线方向

- **不做 Markdown / Obsidian 导出**——只入不出。
- **不做双向同步、实时同步、增量 watch**——每次导入都是用户手动发起的一次性操作。
- **不做 Obsidian 插件**。
- **不做 Git 拉取 / 远程仓库导入**——仅本地文件与文件夹。
- **不做双链关系图谱、反向链接、附件与图片导入**。

### 11.2 仿真沙盒方向

- **不做完整车间沙盒**。以下均不在本阶段：
  - 设备建模、设备状态、OEE 计算、设备故障维修流程
  - 人员 / 班组 / 技能资质 / 派工签收
  - APS 有限产能排程、甘特图、紧急插单与优先级调整
  - 多工厂模型切换（阀门厂 / 电机厂 / 电器装配厂）
  - 成本核算、财务报表、库存计价
  - WMS 对接、入库单、条码 / 批次追溯链
  - 并行工序、工序分支、委外工序
- **不做奥来电器断路器真实流程**——首期使用通用离散制造示例，真实流程留待素材替换阶段。
- **不做 3D 车间、物理引擎、真实设备联机**。
- **不做多人协同画布 / 实时协作**。
- **不做 AI 自动生成工艺路线或 AI 批改**。
- **不做作品集导出与求职展示**（P1 路线图项，非本阶段）。

### 11.3 平台层面

- **不做路由库迁移**（TanStack Router 的取舍属于架构师决策，不由本 PRD 推动）。
- **不做部署形态变更**。
- **不做用户账号体系改造**——沿用现有匿名 `anon_id` 机制。
- **不做教师端 / 班级管理 / 成绩导出**。

## 13. 数据埋点方案

事件命名规范 `{对象}_{动作}`；每个事件附带 `anon_id`、`timestamp`、`device`、`version`；不采集 IP，不上报 Markdown 原文内容。

| 事件类别 | 事件名 | 关键属性 | 回答什么问题 |
|---|---|---|---|
| 获客 | `builder_page_view` | `entry_source` | 用户从哪进入搭建器 |
| 激活 | `route_first_built` | `node_count` | **首次成功搭出一条合法路线**——本阶段最关键的激活指标 |
| 激活 | `simulation_first_run` | `node_count`, `result` | 首次点击运行 |
| 核心行为 | `block_dropped` | `block_type` | 哪些工序块最常被使用 |
| 核心行为 | `simulation_run` | `node_count`, `duration_ms`, `result` | 运行频次与成功率 |
| 学习效果 | `rule_triggered` | `rule_id` (R1-R6), `level_id` | **哪条铁律最常被触发**——直接反映最难理解的概念 |
| 学习效果 | `rule_resolved` | `rule_id`, `attempts` | 用户是否真的靠解释卡修正了错误（修正闭环率） |
| 学习效果 | `explain_card_expanded` | `rule_id` | 解释卡是否被真正阅读 |
| 留存 | `level_started` / `level_completed` | `level_id`, `duration_ms`, `attempts` | 六关的通关漏斗与卡点关卡 |
| 留存 | `session_start` | — | DAU / 使用频次 |
| 流失 | `builder_abandoned` | `last_action`, `node_count` | 用户在哪一步放弃 |
| 内容管线 | `import_started` / `import_completed` | `file_count`, `success_count`, `fail_count` | 导入成功率 |
| 异常 | `error_occurred` | `scope`, `code` | 前端与接口错误 |

**上线后需要重点观察的两个指标：**

1. **激活率** = `route_first_built` 用户数 / `builder_page_view` 用户数。低于 40% 说明画布上手门槛过高。
2. **修正闭环率** = `rule_resolved` / `rule_triggered`。这是验证「业务解释卡真的教会了人」的唯一硬指标；若显著低于 60%，说明解释卡写得不够具体，需要重写文案而不是加功能。

## 14. 开放问题（需总监/架构师拍板）

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| Q1 | 画布实现选原生 Canvas 还是引入 React Flow（`@xyflow/react`，MIT）？ | 路线图文档倾向原生 Canvas 以避免依赖；但 React Flow 自带拖拽/缩放/平移/连接点/小地图，且节点即 React 组件，与现有 plain CSS + design-tokens 兼容，可显著降低 F2 的 Effort | **属架构师决策域**。本 PRD 只提出硬约束：必须路由级懒加载、必须支持自定义节点渲染与连接合法性校验、必须提供键盘可达替代路径 |
| Q2 | 关卡定义存 D1（`fault_scenarios` + `block_solutions`）还是先硬编码为前端常量？ | 影响内容迭代速度 | 建议直接落 D1，两张表已预留，避免二次搬迁 |
| Q3 | 仿真时间尺度如何呈现——真实秒数还是抽象节拍？ | 影响 F4 动画与标准工时的教学表达 | 建议用抽象节拍（1 节拍 = 1 标准工时单位），并允许倍速，避免长工时工序让用户干等 |
| Q4 | 方案保存落 D1 还是 localStorage？ | 影响 F8 与离线策略 | 建议 v1 用 localStorage 保底 + D1 异步同步，保证断网不丢成果 |
