# 研究结果分析框架与模板

> 配套《用户研究计划书.md》。本文件规定：原始数据 → 结论 的标准流程，确保分析可复现、可追溯、可交付。
> 适用：访谈主题分析、问卷统计、可用性指标、三角验证、假设验证矩阵、发现→建议。

---

## 一、数据整理流程（Data Pipeline）

```
原始数据                    整理                     分析                    交付
───────────          ───────────          ───────────          ───────────
访谈录音/录屏  ──→  逐字转录(verbatim) ──→  开放编码 ──→  主题地图 ──→  画像/旅程图
问卷回收      ──→  清洗+分层标签      ──→  描述/交叉统计 ──→  分布+量表 ──→  假设验证(量)
可用性录屏    ──→  任务指标表         ──→  完成率/时长/SUS ──→  问题清单 ──→  可用性报告
竞品/内容审计 ──→  基准笔记           ──→  外部对比     ──→  差异点   ──→  设计建议
        │                                                        │
        └────────────────── 三角验证表 ─────────────────────────┘
```

**铁律**：每条结论必须能回溯到原始数据（访谈编号 / 问卷题号 / 任务编号）。不写"用户普遍认为"这类无来源断言。

## 二、访谈编码方案（Thematic Analysis）

### 2.1 开放编码（标签体系，初版，研究中可增删）
按研究问题预置标签，避免无结构：

| 主题域 | 示例标签 |
|---|---|
| 动机 | `#转岗` `#求职` `#考证` `#兴趣` `#单位要求` |
| 心智 | `#无概念` `#误解_BOM` `#误解_工单` `#流程不清` |
| 行为 | `#碎片学` `#跳读` `#关页面` `#怕SQL` `#要反馈` |
| 入口 | `#不知从哪` `#选过载` `#要地图` `#要续学` |
| 讲解 | `#要例子` `#要术语解` `#要小节` `#稠密劝退` |
| 坚持 | `#看进度` `#做出来` `#作品集` `#闯关` `#对人` |

### 2.2 轴向编码（归类）
把开放标签归入上层主题，例如：
- `#无概念` + `#误解_BOM` + `#流程不清` → **"前理解缺失"** 主题
- `#不知从哪` + `#选过载` → **"起点焦虑"** 主题
- `#怕SQL` + `#要反馈` → **"SQL 悬崖"** 主题

### 2.3 主题地图 + 引用
每个主题保留 2–3 条 verbatim 原话作为证据。示例：
> 主题「起点焦虑」：参与者 P03「一打开看到十二个框，我根本不知道点哪个，就关了。」
> 主题「SQL 悬崖」：参与者 P07「那个空框框光标在闪，我直接往下划走了。」

## 三、问卷分析方案

1. **描述统计**：各题频数 / 百分比 / 均值，画出动机与痛点的分布。
2. **分层交叉**：动机(转岗/求职/兴趣) × 设备 × 痛点量表，看是否存在子群体差异（用于验证画像3）。
3. **量表信度**：Part3 / Part4 做 Cronbach's α，目标 ≥ 0.7；低于则合并或删除题项。
4. **Likert 聚合**：把"功能假设态度"均值排序，识别最被买账 / 最不被买账的功能。
5. **开放题**：用访谈同套标签做词频 + 主题归并。

## 四、可用性指标定义

| 指标 | 定义 | 目标（参考） |
|---|---|---|
| 任务完成率 | 成功完成人数 / 总人数 | ≥ 80% |
| 任务时长 | 从开始到完成的中位秒数 | T0 ≤ 60s；T1 ≤ 6min |
| 错误数 | 操作错误 / 误点击次数 | 越低越好 |
| 求助次数 | 主动问主持人的次数 | 记录，高=设计缺陷 |
| SUS | 标准化可用性量表 10 题（0–100） | ≥ 68（行业平均） |
| 情绪标记 | 录屏中皱眉/叹气/笑 的出现时刻 | 定位卡点 |

## 五、三角验证表（模板）

把同一假设的不同方法结论并排，判断是否一致：

| 假设 | 访谈结论 | 问卷结论 | 可用性结论 | 审计基准 | 综合判定 |
|---|---|---|---|---|---|
| H5 稠密散文掉队 | P02/P05 卡前2屏 | Part3 均值 4.1 | T1 完成率 55% | 竞品均做小块 | **成立** |
| H10 作品集驱动 | F2 多数想要 | Part5 均值 3.8 | — | — | **待补问卷量** |

综合判定取值：**成立 / 需修正 / 推翻 / 证据不足**。

## 六、假设验证矩阵（最终交付，由《用户画像与研究假设.md》H1–H10 升级）

| 假设 | 原假设 | 验证结果 | 证据 | 对 PRD 的影响 |
|---|---|---|---|---|
| H1 年龄主群 | 25–35 转岗 | 成立 | 问卷 68% | 维持画像1 |
| H3 零基础 | 普遍没概念 | 需修正 | 部分有车间直觉 | 补充画像2权重 |

> 每条须附：证据来源（访谈/问卷题号/任务指标）+ 置信度（高/中/低）。

## 七、发现 → 建议 模板

每个发现转成一条可执行建议，含影响 / 工作量 / 度量：

```
【发现】零基础用户在 12 节点全景前平均犹豫 40s，3/8 直接关页面（可用性 T0）。
【假设对应】H4 起点焦虑
【建议】F1 单一「从这里开始」CTA 必须优先落地，其余节点降权。
【影响】降低首屏放弃率（预期 -30%）
【工作量】低（前端）
【度量】新用户首会话完成第1章比例（目标 ≥ 60%）
【优先级】高
```

## 八、研究报告结构（最终交付物骨架）

1. 研究概览（目标 / 方法 / 样本 / 周期）
2. 关键发现摘要（5 条以内）
3. 验证版用户画像（2–3 个，含原话）
4. 零基础学习者旅程图（含情绪与卡点）
5. 可用性测试报告（指标 + SUS）
6. 假设验证矩阵（H1–H10 逐条）
7. 设计建议清单（高/中/低 + 影响/工作量/度量）
8. 研究局限与后续研究建议
