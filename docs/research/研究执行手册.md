# 研究执行手册（Runbook）· 零基础用户研究

> 配套：`用户研究计划书.md` / `研究工具包.md` / `用户画像与研究假设.md` / `研究结果分析框架与模板.md`
> 本手册把"计划"落为"可执行的工具链 + 步骤"。AI 负责**自动化部分**（问卷仪器 + 分析脚本），**人工部分**（招募、访谈、可用性实测）由你/PM 线下执行。

---

## 0. 角色与分工

| 环节 | 谁做 | 自动化程度 |
|------|------|-----------|
| 招募筛查 | 你 / PM 发问卷星或本 `survey.html` 链接 | 问卷仪器已生成 |
| 深度访谈（8–12 人） | 主持 + 记录，按 `研究工具包.md` ② 提纲 | 提纲已就绪，需人工 |
| 可用性测试（5–8 人） | 主持 + 录屏，按 `研究工具包.md` ④ 脚本 | 脚本已就绪，需人工 |
| 在线问卷（≥100 人） | 发 `survey.html` / 问卷星 | 仪器已生成 |
| 数据回收 + 分析 | `analyze_responses.py` 自动算 SUS / α / 假设矩阵 | **全自动** |
| 假设验证矩阵 | 脚本输出 + 人工复核 | 半自动 |

## 1. 工具链产物（本目录）

| 文件 | 作用 |
|------|------|
| `survey.html` | 可部署的**招募筛查 + 在线问卷 + SUS** 三合一仪器；参与者填完自动导出 JSON |
| `analyze_responses.py` | 读取导出 JSON → 输出 SUS 均值、Cronbach's α、分布、交叉表、**H1–H10 假设验证矩阵**、研究报告草稿 |
| `零基础适配体验审计-v1.md` | 上线前的代码+设计启发式评估（本研究的"推断"基线，供三角验证对照） |

## 2. 四步执行

### Step 1 · 部署问卷
- 本地预览：`python -m http.server` 后打开 `survey.html`；或部署到任意静态托管（CF Pages / 问卷星导入亦可）。
- 筛查逻辑已内置：Q1=「是」(从业者) 或 Q4=「无」(无意愿) 自动终止并致谢，不进入正式问卷。
- 参与者提交后浏览器下载 `response-<id>.json`；或配置 `COLLECTOR_URL` 让其 POST 到收集端点（见 Step 4 可选）。

### Step 2 · 回收数据
- 方式 A（轻量）：参与者把下载的 JSON 发回，你汇总进 `responses/` 目录（每文件一行 JSON，或合并为一个 JSON 数组）。
- 方式 B（规模化）：接 `COLLECTOR_URL` 写到 D1 `research_responses` 表（需建表，见 Step 4）。

### Step 3 · 跑分析
```bash
python research/analyze_responses.py responses/   # 目录含 *.json
# 或单文件：
python research/analyze_responses.py responses/batch.json
```
输出：
- `research/OUTPUT-report.md` —— 研究报告草稿（含 SUS、α、分布、假设矩阵）。

### Step 4 ·（可选）服务端收集端点
若要做到 ≥100 人规模化且免人工收文件，可在 Worker 加：
```sql
CREATE TABLE research_responses (
  id INTEGER PRIMARY KEY,
  payload TEXT NOT NULL,      -- 完整 JSON
  kind TEXT NOT NULL,         -- screener|full
  created_at INTEGER NOT NULL
);
```
并暴露 `POST /api/v1/research/submit`（限流、匿名、不存 PII，呼应 `用户研究计划书.md` §5 伦理）。`survey.html` 设 `COLLECTOR_URL` 即自动 POST。

## 3. 人工部分（AI 不能代做）

- **访谈 / 可用性实测**：按 `研究工具包.md` ② ④，5–8 人可发现约 80% 可用性问题；录屏 + SUS 收尾。
- **编码**：访谈逐字稿按 `研究结果分析框架与模板.md` 二 做开放/轴向编码，原话留痕。
- **三角验证**：把访谈/问卷/可用性三方结论并排（框架 §五），逐条标 成立/需修正/推翻。

---

## 4. 成功判据（沿用计划书 §8）

- 每个 RQ 至少 2 种方法交叉印证。
- H1–H10 全部标注 成立/需修正/推翻。
- SUS ≥ 68（行业基准）；任务完成率 ≥ 80%；T0 ≤ 60s 定位 CTA。
- 至少 3 条高优先级建议被产品采纳排期。
