## 0. 为什么现在要做用户研究（研究必要性）

团队已为「零基础新人」做了大量设计决策（单一「从这里开始」入口、分阶段学习序、真实业务数据例子、SQL 三阶梯、术语点即解），但这些全部基于 PM 假设的「转岗小陈」画像，**从未经过一手研究验证**。

主要风险：如果真实用户与假设不符（例如人群更年轻、动机是考证而非转岗、或根本不使用手机碎片时间），已规划的 MVP 方向可能整体偏离，造成内容重写与开发返工。

本计划用**混合方法**，把"假设"变成"证据"，并直接产出《假设验证矩阵》逐条标注 PRD 假设"成立 / 需修正 / 推翻"。

## 1. 研究目标与核心研究问题

### 1.1 研究目标
1. 摸清目标人群的**真实构成、入行动机与触发场景**。
2. 定位零基础学习者在「工厂全貌 → 细节」路径上的**真实卡点与放弃点**。
3. **验证 / 证伪**现有产品假设（PRD 中的画像与功能假设）。
4. 产出可落地的：验证版用户画像、学习者旅程图、可用性基线、**假设验证矩阵**。

### 1.2 核心研究问题（RQ）

| 编号 | 研究问题 | 对应产品假设 |
|---|---|---|
| RQ1 | 谁会来学？为什么想入行 MES/ERP 工厂实施顾问？什么触发了学习意愿？ | 画像「转岗小陈」(25–35, 非制造非 IT) |
| RQ2 | 零基础者对「工厂 / 工单 / BOM / 报工」有什么前理解？如何心智建模"一张订单在工厂里怎么走完"？ | 术语密集散文导致首段掉队 |
| RQ3 | 真实的学习节奏、设备、时长、中断与放弃点是什么？ | 晚上/周末、15–30 min、手机或笔记本、2 屏不懂就关 |
| RQ4 | 从「工厂全貌 → 细节」的渐进路径是否成立？单一入口是否真降低选择过载？ | F1 单一入口、F2 分阶段、F9 首页「继续学」优先 |
| RQ5 | "真实数据例子 + 术语点解 + SQL 三阶梯"是否比当前稠密散文更易懂？SQL 悬崖是否被接住？ | F3/F4/F5/F6 四杠杆 |
| RQ6 | 学习者是否以"能讲清流程""作品集 / 求职"作为成功标准？作品集 / 闯关是否为坚持因素？ | CareerRoadmap、Portfolio 方向 |

## 2. 研究方法（混合方法 + 三角验证）

采用**定性为主、定量为辅、竞品 / 内容审计并行**的混合设计，用 4 种方法交叉印证同一假设，避免单一方法偏差。

| 阶段 | 方法 | 样本 | 主要回答 | 周期 |
|---|---|---|---|---|
| 探索 | 1:1 深度访谈（半结构） | 8–12 人 | RQ1 / RQ2 / RQ3 / RQ6 | 第 1–2 周 |
| 行为 | 可用性测试（think-aloud） | 5–8 人 | RQ4 / RQ5 | 第 2–3 周 |
| 量化 | 在线问卷 | ≥ 100 人 | 全部（验证分布） | 第 3–4 周 |
| 并行 | 竞品 + 内容审计（已有基础） | — | RQ4 / RQ5 外部基准 | 全程 |

**三角验证逻辑**：访谈回答"为什么"（动机/心智），可用性回答"能不能"（行为/卡点），问卷回答"多少人"（分布），审计提供外部基准。任一结论需 ≥ 2 种方法交叉印证方可写入最终建议。

## 3. 参与者标准与样本量

### 3.1 主要人群（核心样本）
- **零基础**：无制造 / IT 系统背景，未写过 SQL，未进过车间。
- **有入行意愿**：明确想入行 MES / ERP / 工厂数字化实施顾问（转岗 / 求职 / 兴趣）。

### 3.2 次要人群（对比样本）
- 制造业一线转数字化岗：懂车间实物，缺系统抽象（可跳过铺垫直接进结构）。

### 3.3 排除标准（避免污染"零基础"结论）
- 已是 MES / ERP 从业者、实施顾问。
- 纯开发者 / DBA（动机与痛点不同，非本产品目标）。

### 3.4 样本量与统计依据
- **访谈 8–12 人**：主题分析（thematic analysis）理论饱和通常在 8–12 人达到。
- **可用性 5–8 人**：Nielsen 经验，5 名参与者可发现约 80% 的可用性问题。
- **问卷 ≥ 100 人**：可在 95% 置信、±10% 误差内估计主要比例；若做 3–4 个细分分层（动机 × 背景），建议 **150–200 人**。

> 招募优先级：主要人群占 70%，次要人群占 30%。详见《研究工具包.md》筛查问卷。

## 4. 研究协议与排期（4 周）

| 周次 | 关键动作 | 产出 |
|---|---|---|
| W1 | 定稿访谈脚本 + 招募筛查 + 启动访谈 | 访谈录音 ×4–6 |
| W2 | 完成访谈 + 转录 + 初步主题 → 可用性脚本定稿 | 访谈转录 + 主题草图 |
| W3 | 执行可用性测试 → 问卷定稿与发放 | 可用性指标原始数据 |
| W4 | 问卷回收 + 统计 → 三角验证 + 研究报告 | 问卷统计 + 研究报告 |

**单次会话结构（访谈 / 可用性通用 60 min）**
- 暖场 + 知情同意（5 min）
- 背景与动机（10 min）
- 核心任务 / 提问（35 min）
- 回顾与开放反馈（10 min）

---

## 5. 伦理与数据治理
- **知情同意**：录音 / 录屏 / 数据用途事前告知，可随时退出。
- **匿名化**：使用 anon_id，不收集姓名 / 手机号，仅采集人口学**区间**。
- **数据安全**：存储于项目私有空间，参与者可要求撤回并销毁数据。
- **客观呈现**：分析时主动防范确认偏误，假设被推翻的结论同样记录。

## 6. 分析计划
详见《研究结果分析框架与模板.md》：
- 访谈：开放编码 → 轴向编码 → 主题地图。
- 问卷：描述统计 + 交叉表（动机 × 背景）+ 量表信度（Cronbach's α）。
- 可用性：完成率 / 任务时长 / 错误数 / 求助次数 / SUS 满意度。
- 三角验证表 + 假设验证矩阵。

## 7. 最终交付物
1. **验证版用户画像**（2–3 个，含真实语录与证据来源）
2. **零基础学习者旅程图**（含情绪曲线与卡点）
3. **可用性测试报告**（任务指标 + 满意度 + SUS）
4. **假设验证矩阵**（PRD 10 条关键假设逐条：成立 / 需修正 / 推翻）
5. **设计建议清单**（高 / 中 / 低优先级，含影响 / 工作量 / 度量）

---

## 8. 成功指标（研究质量）
- 每个 RQ 至少有 **2 种方法交叉印证**。
- PRD 中 **10 条关键假设**全部被标注"成立 / 需修正 / 推翻"。
- 至少 **3 条高优先级设计建议**被产品采纳排期。
- 研究结论可追溯至原始数据（traceable），形成可复用的研究仓库。
