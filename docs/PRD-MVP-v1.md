# MES 实施运维实训平台 — MVP PRD v1

> 作者：许清楚（产品经理） · 日期：2026-07-31
> 依据：现有代码实测（commit ab20ea6）+《后端架构方案-v1》+《生产规范-SKILL-v2》
> 目标：交付一个**可上线、浏览器中能真实使用**的最小实训闭环

---

## 1. 问题陈述

MES（制造执行系统）实施与运维岗位的新人，需要同时掌握**业务概念**（工单、报工、追溯、设备状态）和**SQL 排查能力**（现场问题 80% 靠查库定位）。

现在怎么解决的：看 PDF 文档 + 师傅带。
为什么不行：
- 文档是静态的，看完不会写 SQL；
- 想练 SQL 需要搭一套 MES 库，新人搭不起来，也不敢在生产库上练；
- 学到哪了没人知道，师傅无法判断新人是否具备上岗能力。

**核心痛点**：理论与动手练习是断裂的，且练习环境的搭建成本高于学习本身。

---

## 2. 目标用户

**主要用户：MES 实施/运维新人（学员）**
- 年龄 22–30，工科背景，刚入职 0–12 个月
- 技术水平：懂基础 SQL 语法，但没在真实业务表结构上查过问题
- 场景：入职培训期、项目待命期，用自己的笔记本，网络环境不稳定
- 诉求：看一段理论，马上能在真实表结构上练一次，并知道自己练对没有

**次要用户：培训负责人（管理员）**
- 场景：需要录入/维护课程内容，查看学员练习完成情况
- 诉求：内容可编辑、不用改代码就能加主题

## 3. 竞品分析（简）

内部培训平台，竞品仅作定位参考，不做详细矩阵。

| 竞品 | 核心功能 | 优势 | 劣势（真实短板） | 定价 |
|---|---|---|---|---|
| SQLZoo / LeetCode Database | 在线 SQL 练习 + 判题 | 判题成熟、题量大 | 表结构是通用玩具库（学生/选课），**与 MES 业务零关联**，学完不会查工单 | 免费 / 会员制 |
| 企业内网 Confluence + PDF | 理论文档沉淀 | 编写成本低 | **纯静态**，无练习、无进度、无反馈 | 随 Atlassian 授权 |
| 钉钉/企业微信 培训模块 | 课程 + 考试 + 学时统计 | 组织架构打通、考勤合规 | 只能做选择题考试，**无法承载 SQL 动手实训** | 按人头 |
| Moodle / 开源 LMS | 完整课程体系 | 功能全 | 重部署、需服务器与 DBA，**单人项目维护不起** | 免费但运维成本高 |
| 本地装 MySQL + 自建样例库 | 完全真实 | 最贴近生产 | **新人装不起来**，环境问题劝退率极高，无统一题目与判题 | 免费 |

**我们的差异化**：
用 **MES 真实业务表结构**（work_orders / equipment / products）承载 SQL 练习，且练习环境在**浏览器里零安装启动**（sql.js WASM），理论与练习在同一页面内闭环。SQLZoo 有判题但没有 MES 业务；内网文档有 MES 业务但没法练。我们是唯一把两者合一的。

## 4. 当前代码完成度 vs MVP 缺口（实测结论）

已实测代码 2936 行，结论：**地基质量高，但内容与闭环为零**。

### 已具备（可直接复用，不要重造）
- 后端四层架构、洋葱中间件、统一响应、错误码分区、HMAC 会话、L2 缓存、DO 限流 —— 工程质量好
- 路由表已覆盖 27 个端点：content / progress / quiz / sql-exercises / learning-paths / certifications / admin CRUD / 导入
- Repository 层齐全（admin / cert / chapter / lp / progress / quiz）
- schema.sql 14 张表建表完整
- 浏览器端 sql.js 沙箱可跑（内置 products / equipment / work_orders 样例库）
- `markdown-it` + `dompurify` **依赖已安装**（章节正文渲染的前置条件已就绪）

### 致命缺口（MVP 必须补，按严重度排序）

| # | 缺口 | 实测证据 | 后果 |
|---|---|---|---|
| G1 | **零内容种子数据** | `schema.sql` 全文仅 `INSERT` 了 `platform_config` 两行；topics / chapters / questions / sql_exercises / learning_paths 无任何数据 | 部署上线后**每个页面都是"暂无课程（待后台导入）"**，平台等于空壳，无法演示 |
| G2 | **无章节阅读页** | 前端无 `/courses/:id` 或章节详情路由；`api.chapter()` 已定义但**无任何页面调用**；`markdown-it` 已装但零引用 | 后端能返回正文 `md`，但用户**在浏览器里读不到任何一个字的课程内容** |
| G3 | **SQL 练习闭环断裂** | `SqlSandbox()` 无 props，`SEED_SQL` 硬编码；QuizPage 的"前往沙箱练习"是 `<a href="/sql-space">` 整页跳转，**题目上下文丢失** | 题目和练习环境是两个孤岛，用户看到题目后无法在对应数据集上作答 |
| G4 | **判题不存在** | `submitSqlSvc` 返回 `{received:true}` 桩；选择题**只有 list 接口，无提交判题路由** | 练完不知道对错，学习无反馈 |
| G5 | **进度未接线** | `api.postProgress` 已定义但前端**零调用**；`grep progress web/src` 仅命中 endpoints.ts 定义 | 进度表永远为空，"学到哪了"无法回答 |
| G6 | **学员无身份** | 仅有 `ADMIN_PASSWORD` 单口令管理员登录，无学员账号 | `progress` 需要 `userId`，但学员端无处获取 |
| G7 | QuizPage 需手输数字主题 ID | `<input type="number" value={topicId}>` | 用户不知道该填几，可用性不合格 |

### 需架构师决策的设计冲突（已发现，P0 阻塞）

**SQL 判题的答案泄露风险（R6）**：
现有注释写"判题在客户端 sql.js 内跑 userSql 与 answer_sql 的结果集比对"。但客户端要比对 `answer_sql`，就必须把 `answer_sql` 下发到浏览器 —— 这与《方案》R6"答案不下发"直接矛盾，F12 可直接看到答案。

**建议方案（零 D1 写入成本）**：种子阶段预计算标准答案结果集的**规范化哈希**，存入 `sql_exercises.expected_hash`；下发时只给 hash，客户端跑完自己的 SQL 后对结果集做同样规范化并哈希比对。答案 SQL 永不出服务端。需架构师确认列名与规范化算法（列顺序、类型、NULL、浮点精度处理）。

## 5. MVP 范围

**一句话**：让用户打开网址，能读到真实的 MES 课程内容，能在对应数据集上写 SQL 并立刻知道对错，并且能看到自己练了多少。

即核心闭环：**内容浏览 → SQL 练习 → 判题反馈 → 进度记录**

| F2 | 章节阅读页（主题→章节列表→正文 Markdown 渲染） | 10 | 3 | 100% | 2.5 | **12.0** | P0 |
| F3 | SQL 练习页（沙箱接收题目数据集 + 判题反馈） | 9 | 3 | 100% | 3.5 | **7.7** | P0 |

## 6. 种子内容规格（F1 细化）

平台没有内容就没有意义。种子数据是 MVP 的**内容底座**，不是"假数据"，须按真实培训教材质量编写。

**交付物**：`worker/src/migrations/seed.sql`，与 `schema.sql` 分离，可独立、可重复执行（`INSERT OR IGNORE` + 显式主键 id）。

**内容结构（3 个主题，覆盖 MES 核心域）**：

| 主题 slug | 标题 | 章节数 | SQL 题 | 选择题 |
|---|---|---|---|---|
| `mes-basics` | MES 基础与主数据 | 3 | 3 | 6 |
| `work-order` | 工单与生产执行 | 4 | 5 | 8 |
| `equipment-ops` | 设备管理与运维排障 | 3 | 4 | 6 |

**质量要求**：
- 章节正文为真实可读的 Markdown 教学内容（每章 300–800 字，含表结构说明与业务解释），**禁止 "Lorem ipsum"、"Welcome to"、"这是示例内容" 一类占位文案**
- SQL 题的 `dataset_json` 须复用沙箱现有 MES 表结构（products / equipment / work_orders），必要时按题目扩展字段，保持业务自洽
- SQL 题按难度递进：单表查询 → 条件过滤/聚合 → 多表 JOIN → 子查询/分组统计
- 每题 `prompt` 用业务语言描述（例："查出车间 A 中所有状态为停机的设备及其名称"），而非"写一个 SELECT 语句"

## 7. 验收标准（EARS 格式）

> EARS：While/When/If/Where + 系统 + 必须/应该 + 行为

### F1 种子内容数据
- **当** 管理员对全新 D1 库依次执行 `schema.sql` 与 `seed.sql` 后，系统**必须**包含 3 个 `status='published'` 的主题、10 个章节、12 道 SQL 题、20 道选择题、2 条学习路径。
- **当** `seed.sql` 被重复执行第二次时，系统**必须**保持数据行数不变且不抛出主键冲突错误。
- **在** 任一章节正文中，系统**必须不**包含 "Lorem ipsum"、"Welcome to"、"TODO"、"示例文本" 等占位字符串。
- **当** 用户请求 `GET /api/v1/topics` 时，系统**必须**返回长度为 3 的非空数组。

### F2 章节阅读页
- **当** 用户在课程页点击某个主题卡片时，系统**必须**导航至该主题的章节列表并按 `sort` 升序展示全部已发布章节。
- **当** 用户点击某个章节标题时，系统**必须**加载 `GET /api/v1/chapters/:id` 并将 `md` 字段渲染为格式化 HTML（标题、列表、代码块、表格可见）。
- **在** 渲染 Markdown 正文前，系统**必须**先经 DOMPurify 净化，**必须不**将未净化的 HTML 传入 `dangerouslySetInnerHTML`。
- **若** 请求的章节不存在或 `status` 非 `published`，则系统**必须**展示"该章节不存在或未发布"提示，**必须不**显示白屏或抛出未捕获异常。
- **在** 章节正文加载期间，系统**应该**展示骨架占位而非空白区域。

### F3 SQL 练习闭环
- **当** 用户从题目列表点击某道 SQL 题时，系统**必须**在同一页面内打开练习视图，并用该题 `datasetJson` 初始化 sql.js 数据库，**必须不**发生整页跳转导致题目上下文丢失。
- **在** 练习视图中，系统**必须**同时展示题目描述、当前数据集的表结构、SQL 编辑区与结果区。
- **当** 用户点击"运行"时，系统**必须**在浏览器内执行该 SQL 并以表格展示结果集，**必须不**向后端发送该 SQL 语句。
- **若** 用户提交的 SQL 语法错误，则系统**必须**在结果区展示数据库返回的错误信息并保留用户已输入内容，**必须不**清空编辑器。
- **当** 用户点击"提交判题"且结果集与标准答案一致时，系统**必须**展示通过状态并触发一次进度上报。
- **当** 用户提交结果不一致时，系统**必须**提示未通过并允许无限次重试。
- **在** 任何情况下，系统**必须不**向浏览器下发 `answer_sql` 字段（以浏览器网络面板中不出现答案 SQL 明文为准）。
- **在** 首次进入练习视图时，系统**应该**在 3 秒内完成 sql.js WASM 初始化，**应该**在加载期间展示明确的初始化提示。

### F4 学员匿名身份
- **当** 用户首次访问站点且本地无学员标识时，系统**必须**生成一个 UUID 作为 `userId` 并持久化到 localStorage。
- **在** 用户后续访问期间，系统**必须**复用同一 `userId`，**必须不**每次刷新生成新值。
- **若** localStorage 不可用（隐私模式），则系统**必须**降级为会话内临时标识并保证页面功能正常，**必须不**阻断内容浏览与 SQL 练习。

### F5 进度记录与统计
- **当** 用户通过一道 SQL 题时，系统**必须**以携带唯一 `eventId` 的请求调用 `POST /api/v1/progress` 记录 `sql_done` 事件。
- **当** 同一 `eventId` 被重复提交时，系统**必须**保持 `progress_events` 仅存在一行，**必须不**重复累加当日统计。
- **当** 用户访问首页时，系统**必须**展示其当日 SQL 完成数与累计完成数。
- **若** 进度上报请求失败，则系统**必须**保留本次练习的通过状态展示，**必须不**因上报失败而提示练习未通过。
- **在** 用户尚无任何练习记录时，系统**必须**展示引导性空状态（指向第一个推荐练习），**必须不**展示数字 0 的空白面板。

### F6 状态与可用性
- **在** 任一列表页数据为空时，系统**必须**展示说明性空状态文案与下一步操作入口。
- **若** 任一 API 请求失败，则系统**必须**展示错误提示与"重试"按钮，**必须不**无限停留在加载态。
- **当** 用户浏览题目列表时，系统**必须**通过主题下拉选择器筛选，**必须不**要求用户手工输入数字主题 ID。
- **在** 视口宽度 ≥1024px 与 =375px 两种条件下，系统**必须**保证导航、正文与 SQL 编辑区无横向溢出。

## 8. 明确不做（MVP 范围外）

以下能力**本轮不做**，避免范围蔓延：

| 不做项 | 理由 |
|---|---|
| 学员账号注册/登录体系 | MVP 用匿名 localStorage 身份即可验证学习闭环；账号体系涉及密码存储、找回、合规，成本远超收益 |
| 选择题判题（F7） | 需新增后端判题路由与错题落库；SQL 实训才是本平台差异化核心，选择题任何 LMS 都有 |
| 后台内容管理前端页面（F9） | 后端 CRUD 已就绪，MVP 阶段内容通过 `seed.sql` 维护，管理员页面不阻塞上线 |
| Excel 分片导入前端 | 后端 staging→commit 已存在，但无内容规模压力，属过早优化 |
| 证书发放与考核认证 | 依赖完整的进度与考试数据积累，无数据时发证无意义 |
| 排障沙盘 / 积木容错（fault_scenarios、block_solutions） | 交互复杂度最高的模块，需先验证基础闭环是否被使用 |
| 错题本 | 依赖 F7 选择题判题，顺延 |
| 视频媒体（media 表） | 涉及存储与带宽成本，与"零成本"约束冲突 |
| 数据看板 / stats_daily 可视化 | 单人使用场景下，首页今日统计已足够 |
| 多租户 / 组织架构 / 权限分级 | 内部单一培训场景，无此需求 |

## 9. 非功能需求

| 类别 | 要求 | 优先级 |
|---|---|---|
| 性能 | 首屏可交互 < 3s；`/api/v1/topics` p95 < 500ms；sql.js WASM 初始化 < 3s 且不阻塞页面渲染 | P0 |
| 成本 | 严守 Cloudflare 免费额度：单请求 D1 语句 ≤ 40 条；只读接口走 L2 缓存不挂 DO；SQL 执行与判题全在浏览器，零 D1 消耗 | P0 |
| 安全 | `answer_sql` 与选择题 `answer` 字段永不下发；DTO 显式白名单，禁止 `SELECT *` 直出；Markdown 渲染前 DOMPurify 净化；学员端接口无鉴权但必须限流 | P0 |
| 可用性 | 内容与 SQL 沙箱在 API 不可用时仍可展示已缓存内容；进度上报失败不阻断练习 | P1 |
| 兼容性 | Chrome / Edge / Safari 最新两个版本；需支持 WebAssembly；桌面端 1024px+ 为主，375px 移动端不破版 | P0 |
| 可访问性 | WCAG 2.1 AA 基础合规：键盘可达、正文对比度 ≥ 4.5:1、表单控件有关联 label | P2 |
| 国际化 | 中文单语言，不预留 i18n | P2 |
| 数据埋点 | MVP 复用 `progress_events` 记录学习行为即可，不引入第三方埋点 SDK | P2 |

### 图标与视觉约束（团队 P0 绝对规则）

- 功能图标**统一使用 SVG 图标库**（具体选型由架构师锁定），**禁止使用 emoji 充当功能图标**。本文档内提及图标一律用文字描述（如"书本图标""数据库图标""对勾图标"）。
- **禁止紫色到粉色的渐变配色方案**。
- 界面文案须为具体业务语言，**禁止 "Welcome to"、"Lorem ipsum"、"这是一段示例文字" 等模板占位文案**。

| 场景 | 预期行为 |

| 空状态 | 列表为空展示说明文案 + 下一步入口；进度为空展示引导而非 0 面板 |
| 加载状态 | 骨架占位；WASM 初始化有独立提示 |
| 错误状态 | 展示原因 + 重试按钮；不白屏 |
| 章节不存在 / 未发布 | 明确提示，不暴露内部错误码栈 |
| SQL 语法错误 | 回显数据库错误信息，保留输入 |
| SQL 死循环 / 超大结果集 | 结果区最多渲染 200 行并提示已截断 |
| 重复提交同一练习 | 进度幂等，统计不重复累加 |
| 离线 / API 不可达 | sql.js 沙箱仍可运行；内容区提示网络不可用 |
| localStorage 不可用 | 降级为会话内身份，核心功能不受影响 |
| 浏览器不支持 WebAssembly | 明确提示需升级浏览器，其余内容浏览功能正常 |

## 11. 上线判定标准（Definition of Done）

MVP 可上线当且仅当以下全部成立：

1. 全新环境执行 `schema.sql` + `seed.sql` 后，首页可见 3 个真实主题
2. 可从首页点入任一主题，读完一整章图文正文
3. 可打开一道 SQL 题，在浏览器内写 SQL、运行、提交并得到通过/未通过反馈
4. 通过后返回首页，可看到当日完成数 +1
5. 浏览器网络面板中检索不到任何 `answer_sql` 明文
6. `npm run typecheck` 零错误，`npm run build` 通过
7. 全部列表页在无数据时展示说明性空状态而非空白
