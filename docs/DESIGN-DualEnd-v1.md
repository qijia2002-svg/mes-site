## 0. 文档定位与阅读对象

本总纲回答一个问题：**在「MES 实施运维实训平台」现有架构下，如何把"电脑端系统学习"与"手机端碎片学习"作为一个统一产品来统筹，而不是两套割裂的体验。**

- 原则层：定义双端定位、跨端协同规则、操作友好性底线。
- 不越权：不规定具体技术选型（选型由架构师在 Spec 锁定），只规定"做成什么样才算对"。
- 强制约束：凡涉及双端的功能，必须按 §9 模板描述；任何双端产物不得违反 P0 红线（见 §8）。

## 1. 产品定义（一句话）

MES 实训平台是一个**单代码库响应式 SPA**：大屏与小屏**均为体系化学习客户端**——大屏是"系统学习驾驶舱"，小屏是"随身系统学习端"，同一份体系化内容、同一份进度，随设备形态自适应；移动端在保持体系化的前提下强化移动场景体验（触控优先、可中断可恢复、离线可读），绝不因换设备而中断。

## 2. 双端模型 Reality Check（关键重构，必须先读）

你给的系统提示词把"电脑端 / 手机端"写成两个并列产品。**但本平台不是两套代码，而是一个 React 19 + Vite SPA，靠响应式断点切换形态。** 这是制定本总纲的前提，必须在此对齐：

| 真实形态 | 技术事实（来自 README / overview / ADR-013） |
|----------|----------------------------------------------|
| PC 模式（≥1024px） | 深色侧栏驾驶舱导航、可展开分组、体系化内容消费 |
| Mobile 模式（≤768px） | 底部 TabBar（已落地）、触屏优先、体系化内容消费（移动优化） |
| 中间过渡（769–1023px） | 响应式降级，不单独设计，避免第三套布局 |

**关键推论**：
- "跨端协同"的真实成本**不在"端内跳转"**（同 SPA 内 Route 切换零成本），而在**"跨设备 / 跨浏览器"**——即 A 手机看到第 N 张卡片，B 电脑要能接着看。
- 因此本总纲把"双端"定义为**同一应用的两个响应式形态 + 一个可选的跨设备同步层**（见 §5），避免被"两个 App"的假设带偏去重复造轮子。

## 3. PC 与 Mobile 定位（沿用你的系统提示词，落到本平台）

| 维度 | PC（系统学习） | Mobile（随身系统学习） |
|------|----------------|---------------------|
| 用户场景 | 大段专注时间（工位 / 自习） | 零散时间（通勤 / 排队 / 睡前）也可用，但承载完整体系 |
| 主打 | 体系化、深度化 | 体系化 + 移动优化（触控优先、可中断可恢复） |
| 已有载体 | CoursesPage / ChapterPage / SimulatorPage（工艺路线搭建器）/ QuizDeck（卡片考试） | 底部 TabBar + 响应式首页 |
| 内容形态 | 系统课程、长讲义、结构化笔记、作业、测评、进度看板 | 与 PC 同源的体系化课程 / 讲义 / 测评，移动端额外提供速览 / 听读 / 离线等便利形态 |
| 本平台缺口 | 结构化笔记、作业流尚待补 | **长内容移动端可读性、触控导航、离线缓存、一键接力、本地提醒、打卡均未建 / 待强化** |

## 4. 跨端协同原则（你的 6 条，逐条落到本架构）

> 每条给出：原则 → 本架构落地方式 → 当前就绪度 → 待决。就绪度分三档：已就绪 / 部分 / 待建。

### 4.1 同一账号 · 实时云同步
- 落地方式：见 §5 身份与同步模型（L0/L1/L2 分级）。
- 当前就绪度：**L2 账号云同步已启用（2026-08-09 用户反转 + 拍板邮箱密码/强制注册）；L0 匿名基线取消，登录态续学适用于已登录用户**。
- 待决：无（OD-017 已 RESOLVED 升格 ADR-023）。

### 4.2 断点续学
- 原则：手机看到第 N 个卡片，电脑打开自动定位到对应模块；反之亦然。
- 落地方式：定义**统一位置锚** `{ chapterId, cardIndex, scrollAnchor, ts }`，由 `useProgress`（ADR-014 单一数据源）持久化。
- 当前就绪度：**部分**——同会话内 `completedChapterIds` 已持久化；但"卡片级位置锚"需新增字段，跨设备需同步层。
- 待决：位置锚字段是否进 `progress` 表（跨设备同步需此锚点）；认证方式与匿名升级路径待 OD-017 确认。

### 4.3 内容自适应，不硬搬
- 原则：双端同源体系化内容；移动端在保持体系化的前提下，为长内容提供"速览版 / 听读版 / 离线版"等便利形态，让用户在任何场景都能持续推进系统学习，而非把内容砍成碎片。
- 落地方式：内容模型带 `durationSec` / `unitType`（video|article|card|audio）元数据，用于"听读 / 速览"等便利视图的呈现（**非强制拆微单元**）；长内容通过渐进式阅读 + 位置锚（§4.2）保证移动端可中断可恢复；音频版 = TTS 或预录。
- 当前就绪度：**待建**——现有 `chapters` 无 `durationSec` / `unitType` 字段，需 Schema 扩展（关联 OD-003 数值待定）。

### 4.4 一键接力
- 原则：任一端提供"在手机 / 电脑上继续"入口，无需手动搜索。
- 落地方式（分两层）：
  - 同设备切形态：SPA 内悬浮入口，点击仅切换响应式形态（同一 Route），零跳转成本。
  - 跨设备：生成带位置锚的 deep link（`/c/:chapterId?card=N&anchor=...`），目标设备打开即定位；配合 §5 L2 账号同步层拉取锚点。
- 当前就绪度：**跨设备接力随 L2 启用变为可行（deep link + 账号同步锚点）；同设备切形态 L0 即可做**。

### 4.5 离线可用
- 原则：手机端核心复习内容支持离线，适配无信号场景。
- 落地方式：**SQL 沙箱已离线**（sql.js WASM，本地执行，见 README Phase 0）；复习卡片 / 微课元数据由 Service Worker 预缓存（PWA manifest）。
- 当前就绪度：**部分（沙箱已离线；PWA 缓存层待建）**。

### 4.6 提醒克制
- 原则：手机推送基于学习节奏而非营销，可一键免打扰。
- 落地方式：默认不开启推送；基于学习节奏（连续天数 / 待复习量）的**本地通知**（Notification API），可一键免打扰开关；Web Push（需订阅）留 L2。
- 当前就绪度：**待建**。

## 5. 身份与同步模型（解决"匿名 vs 账号"核心张力）

### 5.1 张力来源（必须正视）
- 你的系统提示词假设"同一账号 · 实时云同步 · 零重新登录"。
- 现状：进度是**匿名**的——`anonId` 存 localStorage，无注册（ADR-014）；`OD-001` 已明确"v1 优先保证核心仿真功能可用，不要一开始背负多端同步、冲突合并、登录鉴权大量工作量"。
- 注（2026-08-09 18:30 反转）：用户已决定启用 L2 账号云同步，原 `OD-001`「不背登录鉴权」约束改为「账号体系本期启动」；并拍板**强制注册**（取消匿名 `anonId` 基线，全站需登录门禁）。
- 结论：不能假装账号体系已存在，也不能无视你的跨端诉求。采用**分级渐进模型**。

### 5.2 分级模型（推荐路线）

| 级别 | 名称 | 能力 | 成本 | 落地时期 |
|------|------|------|------|----------|
| **L0** | 同会话续学（基线） | 同一浏览器 / 同一设备内进度自动续；响应式自适应双形态 | 零（已具备） | v1 当前 |
| **L1** | 轻量配对码同步 | 用户生成 6 位配对码，进度加密存 D1；另一设备输码拉取 / 推送差异 | 低（不复用密码体系，不注册） | 可选（L2 启用后降为冗余，待议） |
| **L2** | 完整账号体系 | 注册 / 登录、实时云同步、Web Push、多端同时在线 | 高（鉴权 + 冲突合并） | **启用（用户 18:30 反转，提前启动）** |

> 注：用户选定**强制注册**，`anonId` 匿名基线取消；L2 账号体系为唯一基线，L0 仅指已登录用户的同会话续学。详见 ADR-023 + `SPEC-AccountSync-v1.md`。

### 5.3 决策建议
- **决策（2026-08-09 用户反转 + 拍板）：启用 L2 账号云同步，且为全站唯一基线。** 此前 18:26「L0 暂不启动」意向已撤销（OD-017 重开后再 RESOLVED，升格 ADR-023）。
- **已确认（2026-08-09 用户拍板）**：
  - 认证 = **邮箱 + 密码**（HMAC 会话复用现有 `SESSION_SECRET`；CF Workers + D1 + JWT 自包含，零外部依赖）。
  - 匿名关系 = **强制注册才能用**（用户选定，偏离推荐默认「保留匿名可升级」）：取消 `anonId` 基线，全站内容/学习路由包登录门禁；现有匿名进度不迁移，注册即干净起点（v1.1 可选加一键导入）。
  - 同步范围 = 进度 / 笔记 / 收藏 / 错题 四者双向同步（来自系统提示词）。
  - 冲突策略 = per-field last-write-wins（服务端时间戳），v1 不做 CRDT。
- 影响：需新增 auth 注册/登录端点、`users` 表、`sync` 拉取/推送端点、密码哈希（WASM argon2id）、冲突合并；全站加登录门禁；`ADR-014` 匿名进度模型被覆盖（进度改账号作用域）。
- 下一步：实现契约已落为 `SPEC-AccountSync-v1.md` + ADR-023；确认后进入 Phase 2 设计细化 / Phase 3 开发。

## 7. 手机端体验增强（本期重点，用户指定）

按你的选择，双端统一为体系化学习、并优先"加强手机端学习体验"。以下为 v1.5 手机端增强包——7.1 一键接力（含跨设备，依赖 L2 账号同步）+ 7.2 离线 + 7.3 克制提醒 + 7.4 移动端体系化内容体验打磨。账号云同步已启用（OD-017 反转），跨设备能力随之可行。

### 7.1 一键接力（Handoff）
- **同设备切形态**：任意内容页右上角悬浮入口，图标用 lucide `smartphone` / `monitor`（ADR-002 / ADR-016 锁死 lucide，禁 emoji）；点击仅切换响应式形态（同一 Route），零跳转成本。
- **跨设备接力**：内容页提供"生成接力链接"，写入 `{chapterId, cardIndex, anchor}` 到账号同步层（L2）；目标设备登录同账号后打开 deep link 即定位。
- 验收：在 ≤768px 视口打开接力链接并登录同账号，首屏定位误差 ≤ 1 张卡片。

### 7.2 离线缓存（Offline）
- 复习卡片 / 微课元数据经 Service Worker 预缓存（PWA `manifest` + `sw`）。
- SQL 沙箱已离线（sql.js WASM），无需额外改造——这是本平台离线的天然底座。
- 网络恢复后，账号同步层（L2）做差异同步（仅上传本地新增进度事件）。
- 验收：飞行模式下面卡片复习可正常进行；恢复网络后进度回传成功。

### 7.3 克制提醒（Gentle Nudge）
- 默认关闭推送；首次进入 Mobile 模式时一次性的"学习节奏提醒"开关询问（非营销话术，用真实功能描述）。
- 开启后仅基于学习节奏发**本地通知**（连续中断天数 / 待复习卡片量），不读通讯录、不拉外部数据。
- 全局"免打扰"开关，一键关闭，状态持久化。
- 验收：提醒文案均为功能描述，无营销词；免打扰开关即时生效。

### 7.4 移动端体系化内容可读（Systematic-on-Mobile）
- 长讲义 / 课程页在 ≤768px 下的重排版：字号阶梯、行宽约束、章节锚点跳转、目录抽屉（lucide `list` 图标），保证体系化内容在手机上可读、可导航、不丢结构。
- 触控优先：所有交互热区 ≥ 44px（WCAG 2.5.5），避免 hover-only 操作；PC 的 hover 展开在移动端改为点按展开。
- 测评 / 卡片考试（QuizDeck）在移动端保持完整可用：选项大点击区、进度可见、可中断交卷。
- 验收：在 ≤768px 下完成一门课程的"打开 → 学习 → 测评 → 进度回写"全链路，无需切换到 PC。

## 8. 设计系统约束（锁死，来自 design-system/）

任何双端产物必须满足：
- **Token**：引用 `design-system/design-tokens.css` v3，组件 CSS 零裸 hex（唯一例外 `#fff` / `#000`）。
- **图标**：lucide-react 单一库（ADR-002 / ADR-016），新增语义名走 `Icon.tsx` 注册（OD-005）；**禁止 emoji 作功能图标**。
- **主色**：accent `#0a61b8`（v3，色相 210°）；**禁止紫粉渐变**（Indigo→Pink）。
- **缓动**：禁止弹跳 `cubic-bezier(0.68, -0.55, 0.265, 1.55)`。
- **响应式断点**：≥1024px 驾驶舱 / ≤768px TabBar；中间态不单列。
- **Hero**：禁止千篇一律大图 Hero，首屏展示真实产品内容（进度环 / 待复习卡）。

## 9. 双端功能描述规范（强制执行输出要求）

任何新功能（PRD / 原型 / Spec 条目）**必须**按以下结构描述，缺一项退回：

| 字段 | 必填 | 说明 |
|------|------|------|
| ① PC 行为 | 是 | 大屏下的交互 / 布局 / 内容形态 |
| ② Mobile 行为 | 是 | 小屏下的交互 / 布局 / 内容形态 |
| ③ 协同方式 | 是 | 是否跨端同步，标注 L0 / L1 / L2（见 §5） |
| ④ 场景适配 | 是 | 对"移动场景"与"桌面场景"各自的适配说明（双端均为体系化，描述差异化的 UX 而非内容裁剪） |

**示例（打卡功能）**：
- ① PC：个人中心内"学习打卡"面板，周历热力图，可回顾。
- ② Mobile：首页底部 TabBar 一键打卡，震动反馈，3 步内完成。
- ③ 协同：L0 同设备即时；L1 跨设备同步打卡记录；L2 多端实时。
- ④ 适配：移动场景主打 Mobile 一键打卡（触控优先）；桌面场景 PC 看周历趋势，双端数据同源。
