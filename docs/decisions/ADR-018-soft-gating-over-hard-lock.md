# ADR-018: 渐进路径用软引导，不做硬性关卡解锁

## Status
Accepted (2026-08-08)

## Background

用户反馈的痛点之一是「不知道从哪学起」。常见解法是加关卡：
没学完第一阶段就锁住后面的节点，强制线性推进。

需要判断这是不是对症下药。

## Decision

采用**软引导**：视觉分层 + 单一明确的行动召唤，但所有节点保持可点击。

- 非当前阶段的节点降低视觉权重（既有 token `--meta` / `--border-soft`），不置灰锁死。
- 当前阶段高亮，首屏给一个「从这里开始」按钮指向 `nextKey`。
- 阶段完成度由前端派生层 `useStageProgress` 计算，不落库、不调接口。

## Consequences

**为什么不做硬锁**

1. **技术上会逼出一堆附带成本。** `/api/v1/flowchart/:slug` 是 `noAuth` 公开接口，
   匿名用户就能逛全图。硬锁要判定"你有没有资格看这个节点"，就得服务端持有匿名用户进度——
   要么强制登录（对零基础用户是纯劝退），要么再造一套匿名态存储。两条都不划算。
2. **和"先全貌"的目标直接冲突。** 第一阶段的设计意图就是让人先随便逛一圈建立整体印象。
   锁住等于把这个意图取消掉。
3. **没对准真实痛点。** 用户说的是"不知道从哪学起"——缺的是**指路**，不是**拦路**。
   把节点锁死，只是把"不知道该学什么"换成"什么都点不动"，挫败感更强。

**正面**

- 零后端改动：解锁状态是纯前端派生，不新增接口、不新增存储、不吃 D1 配额。
- 匿名用户体验完整，不被登录墙截断。
- 好奇心强的学员可以自由跳读，路径引导只是默认建议而非强制。

**负面**

- 自制力弱的学员仍可能乱点。用清晰的阶段视觉层次和唯一的主 CTA 缓解，
  不用锁来解决自律问题。
- 「学完了没」的判定完全依赖前端派生，服务端不持有阶段状态。
  本期可接受；若将来要发结业证书之类需要服务端权威判定的功能，届时另开 ADR。
