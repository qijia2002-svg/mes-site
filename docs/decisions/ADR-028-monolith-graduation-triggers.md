# ADR-028: 单体毕业触发器（何时抽 Worker）

## Status
Proposed（待 ARCH-Extensible-v1 升格后转 Accepted）

## Context
用户要求「大型系统的可扩展架构」。常见直觉是「大=微服务」，但既有 ADR 已证当前约束下微服务是负资产。然而完全否定拆分会留下「万一要拆却拆不动」的债。本 ADR 定义**量化触发器**，让拆分在"边界早已钉死"的前提下按需发生，不重写、不预付成本。

## Decision
采用 **触发式毕业（Trigger-based Graduation）**，阈值（示例值，实施前以实测校准）：

| ID | 触发器 | 阈值（示例） | 动作 |
|---|---|---|---|
| T1 | D1 单写线程饱和 | 写 p99 > 300ms 或写错误率 > 1% 持续 7 天 | 写路径再批量化 + 评估只读副本/拆写岛 |
| T2 | DO 限流误伤 | 合法用户被令牌桶误伤率 > 0.5% | 调参或把 ai-judge 拆出减负 |
| T3 | subrequest/CPU 触顶 | 单请求近 50 subrequest 或 CPU 软限告警 | 拆出重算力岛（ai/sim 后端） |
| T4 | 团队规模 | 维护者 > 3 人且同单体冲突频繁 | 按岛分 repo/分责，启动抽取 |
| T5 | 中国可达性 | 某入口域持续不可达 | 增备入口域（沿用 wrangler 多域策略） |

触发器是**必要非充分**条件：抽 Worker 前必须先在 Phase A/B 把岛屿边界钉死（ADR-024/025/027）。抽取 = 把该岛 `routes+migrations+repositories` 移到新 Worker，桥接协议不变（transport 从进程内变 HTTP）。典型首批候选：① `ai-judge`（省主 Worker 算力）② 内容/CDN 只读 Worker（高缓存命中、可独立扩边缘）。

## Consequences
- 容易：不为未发生的规模预付微服务复杂度。
- 容易：真到阈值时无痛抽取，因为边界早已清晰。
- 困难：阈值需实测校准，文档值仅为示例。
- 放弃：预设的微服务拆分，以及「看起来先进」的架构。
