## MES 实训平台 · 后端架构方案 v1

- 依据《生产规范-SKILL-v2.md》（位于 ../2026-07-31-12-11-15/）输出《后端架构方案-v1.md》与 overview.md，写在工作区 2026-07-31-12-26-47 根目录。
- 架构定调：单 Worker 内部四层（core / middleware / modules / data），**明确不做微服务、不做 CQRS、不引消息队列**——免费套餐 + 单人项目下属于负资产。
- 三个关键决策：
  1. 引入 Cache API 三层缓存（L1 isolate 变量 / L2 caches.default / L3 TanStack Query），失效用 `content_version` 版本号换键（免费版无 cache tag purge）。规范 v2 完全未提，是本次最高杠杆增量。
  2. `DbSession` 查询预算守卫，单请求 D1 语句 > 40 直接抛 5002，把纸面约束变成运行时护栏。
  3. 限流只挂敏感端点，避免 DO 请求数≈Worker 请求数导致双额度同时耗尽。
- 发现规范 3 处缺陷（建议回写 v3）：
  1. wrangler.toml 缺 `[[migrations]] new_sqlite_classes = ["RateLimiter"]`，免费版 DO 必须 SQLite-backed，否则 deploy 失败；
  2. Excel 分片导入缺跨请求整体一致性 → 补 staging→commit 两阶段 + import_chunks 幂等表；
  3. `/admin/*` 每请求查 token_version 会成倍吃 D1 额度 → 补 isolate 级 60s TTL 缓存（代价：改密后旧 token 最多多活 60s）。
- 最高风险 R6：缓存的题面接口若误带标准答案，泄露会被固化 300s。强制学员端 DTO 显式字段白名单 + 单测断言。
- 待用户确认的两处权衡：限流挂载范围、token_version 60s 窗口。
