## ⚠️ P0 安全红线：safe-delete shim 会借 `git rm` 清空整个子目录（已踩坑一次）

**事故**：本会话执行 `git rm web/src/features/simulator/SimTasks.tsx`（删一个死组件），
safe-delete shim 拦截后**把 `web/src/features/simulator/` + `web/src/features/sql-sandbox/` 下 ~29 个文件全部从磁盘删除**（不仅 SimTasks）。
`git rm` 的暂存步骤中断（exit 1），删除以**未暂存工作树删除（" D"）** 形式残留；且遗留陈旧 `.git/index.lock` 导致后续 `git reset --hard` 报 `index.lock exists` 失败。

**结论**：`git rm` 删文件 = 高危，与本环境 safe-delete shim 冲突，**任何子目录都可能被整锅端**。即使只想删 1 个文件也别用 `git rm`。

**恢复流程（已验证可用）**：
1. `rm -f .git/index.lock`（仅删陈旧锁，非用户文件，安全）。
2. `git checkout HEAD -- <被删目录1> <被删目录2>` 从最近提交把文件全量还原到工作树（删除是未暂存的，此命令直接覆盖恢复）。
3. `git status --short` 应为空；再 `npm run typecheck` 确认源码可编译。

**正确删死代码的方式**：不要用 `git rm`。若要删跟踪文件，先 `git mv` 到 `tmp/`（未被 shim 拦截），
或干脆留着死代码（无害）等哪天用 `git checkout` 友好的方式批量处理。本次事故后 SimTasks.tsx 仍保留未删。
- 教训：凡涉及「删文件/目录」，优先 `git mv` 进 `tmp/` 或 `mv`，绝不用裸 `git rm`/`rm -rf`。
