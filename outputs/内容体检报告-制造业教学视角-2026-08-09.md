# 内容体检报告 — 制造业新人学习网站

**审计对象**：mes-learning-platform（线上 shuojia.qzz.io）
**审计视角**：制造业业务正确性 + 教学设计有效性（工程侧已有 backend / frontend / qa 三份报告，本报告不重复）
**日期**：2026-08-09

---

## 0. 决策摘要

1. **工程是健康的，真问题在内容闭环。** 类型检查通过、P0 视觉红线 0 违规、15 个 lazy 路由 0 缺失、工厂主线 12 个节点 100% 挂载资源。不要把工程当成主战场。
2. **最严重的缺口是练习闭环断裂**：33 门课有 25 门（76%）一道题都没有，147 章节只有 37 章（25%）有题。学习网站没有检验环节，会退化成电子讲义。
3. **主线在"计划"这一站有专业深度塌陷**：MPS 章节 311 字，把主生产计划讲成"按 product_id 做 GROUP BY 求和"，漏掉时间分段、粗能力校验、可承诺量。这不只是内容薄，是会给新人建立**错误的专业认知**。
4. **主线虎头蛇尾**：起点（客户下单 470 字）和终点（生产入库 312 字、发货出库 303 字）是全线最薄的，而中段 MRP 有 1618 字。第一印象和收尾都损失在这里。
5. **课程元数据是占位数据**：33 门课里 26 门 `estimated_hours=4`，学员一眼能看出是假的，直接损伤平台可信度。

## 3. 做对了的地方（建议保持，不要在重构中丢掉）

1. **六站主线选对了骨架。** "先走一圈 → 计划订单 → 采购齐套 → 生产工单 → 质量检验 → 仓储发运"，这是订单履约主链（O2C 与 P2P 的交汇），是制造业新人建立全局观的正确切法。比按 MES 功能模块切分（工单管理/物料管理/质量管理…）好得多——模块切分是系统视角，主线切分是业务视角，新人需要的是后者。

2. **学习目标写成了行为化目标。** 例如采购站的目标是"能自己查出哪些采购单逾期未到、哪些是到货但短交，不依赖采购报表给的口径"，而不是"了解采购流程"。这是能力导向设计，可验收、可自测，专业水准明显高于同类教程。

3. **单据流贯穿教学。** 用 SO-20260725-01、WO-20260801-02 这样的具体单号串起全流程，是制造业培训最有效的方法——新人对抽象流程无感，对"这张单去哪了"有感。

4. **MRP 章节达到实战级。** 290 台 → BOM 展开含损耗率 → 毛需求 → 减库存 → 净需求，全链数值可追。并且点出了"共用料要先跨产品汇总再减库存，分产品各减会漏"这个新人必踩的坑。这是真做过项目的人才写得出的内容。

## 5. 重点展开：MPS 章节为什么必须改

当前全文（311 字）核心论点是：

> "把评审通过的订单按 `product_id` 分组，数一数有多少张单、加一加总数量，一张主生产计划就出来了。"

**业务上不成立。** 按产品汇总总量得到的是需求汇总表，不是主生产计划。MPS 之所以是"主"计划，在于它要同时满足三件事：

1. **时间分段（time bucket）** — 需求必须落到具体周或月，"总共 290 台"不是计划，"第 32 周 80 台、第 33 周 110 台"才是。
2. **粗能力校验（RCCP）** — 拿关键资源（装配线、瓶颈设备、关键工种）的可用工时去校验这个分段量做不做得出。做不出就要回头调整，这才是计划与汇总的本质区别。
3. **可承诺量（ATP）** — 已排产量减去已承诺客户的量，等于还能对新订单答应多少。这是销售敢不敢接单的依据。

**教学上还有一处断裂。** 上一站 9105《订单评审：接了不等于做得出》立了个问题——凭什么判断做不出？答案本应由 MPS 站的 RCCP 接住，但当前 MPS 只讲聚合，问题悬空了，主线的因果链在这里断开。

**改法建议**（保持 SQL 教学不丢）：
- 保留 GROUP BY，但把它定位成"MPS 的第一步：需求汇总"，明确后面还有两步。
- 加一张周桶分解表：把 290 台按交期拆到周。
- 加一段 RCCP 算例：装配线日产能 25 台 × 5 天 = 125 台/周，对比该周需求 110 台，负荷率 88%，通过；若某周需求 140 台则负荷率 112%，超载，必须前移或外协——这正好接上 9105 的问题。
- SQL 练习顺势升级为"按周聚合并标出超载周"，比单纯 GROUP BY 更有业务含金量。

## 6. 出题建议（针对 P0）

制造业新人的典型症状是"看着都懂，一上手全废"，所以题型比题量更重要。建议主线每站 3 题按这个结构配：

| 题型 | 作用 | 示例 |
|---|---|---|
| 概念辨析题 | 防止混淆相邻概念 | MPS 与 MRP 的分工边界是什么 |
| 场景判断题 | 训练根因定位 | 工单已 released 却开不了工，最可能卡在哪个环节 |
| 数据查证题 | 对接 SQL 沙箱 | 从样例库里挑出逾期未到货的采购单 |

场景判断题是制造业最该重仓的题型，也是当前完全缺失的。

## 9. 建议的执行顺序

1. **先 `git push`。** 22 个 commit 只在单机，这是唯一不可逆的风险，成本 10 秒。
2. **再改 MPS 章节。** 单点改动，直接消除一处业务错误认知，并接回主线因果链，ROI 最高。

5. **回填课程元数据。** 批量 UPDATE，成本低，直接提升可信度。
