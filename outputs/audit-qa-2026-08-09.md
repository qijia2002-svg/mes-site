## 二、P0 视觉红线 — 扫描器本身有缺陷，已当场修复

### 2.1 修复：`scripts/p0scan.mjs` emoji 检测存在假阴性（严重）

原扫描器长期报告「emoji 命中 0」，**这个 0 不可信**。

**根因**：`emojiRe` 带 `/g` 标志，在循环中复用 `.test()`。`RegExp.prototype.test` 在 `g` 模式下会保留 `lastIndex`，跨行调用产生交替漏检。

**变异加固证明**（test-discipline.md §5：注入畏惧缺陷，要求断言变红）：

```
--- 复现 p0scan 的调用方式（模块级 g 正则 + 循环 .test）---
  行1 命中 / 行2 漏检 <<< / 行3 命中 / 行4 命中 / 行5 漏检 <<< / 行6 命中
p0scan 方式命中 4/6          ← 漏检率 33%
正确方式命中 6/6
```

**修复**：`scripts/p0scan.mjs:30` 前插入 `emojiRe.lastIndex = 0;`（唯一写操作，属授权范围）。

**修复后注入自检**：把 6 个已知 emoji 写入临时目录后扫描 → `emoji 功能图标命中: 6`（6/6 全中）。扫描器现在**证明了有探测力**。

### 2.2 修复后的真实扫描结果

```

emoji 功能图标命中: 0
紫粉渐变命中: 0
硬编码色值(非#fff/#000)命中: 0
```

独立交叉验证：ripgrep `#[0-9a-fA-F]{6}\b` 于 `web/src` → **No matches found**。两条独立路径互证，硬编码色值确为 0（色值集中在 `design-system/design-tokens.css`，未被 ROOT 覆盖属设计意图）。

### 2.3 全域扩大扫描（含 `.html` / worker，163 文件）

命中 5 处 emoji，**全部位于代码注释，无一是 UI 功能图标**：

## 三、阻断项（BLOCKING）

### B-1　`POST /api/v1/engine/status` 用户可达路径上确定性返回 HTTP 500

**类型**：正确性缺陷 + 性能盲区（N+1）
**严重度**：P1（用户可达、确定性复现、服务端每次 500；但 UI 静默降级不白屏）

**线上复现**（三组对照，同一时刻）：

```bash
# 场景A：设了 activePath、未选路径 —— 前端真实会发的 body
curl -X POST -d '{"activePath":500}' .../api/v1/engine/status
→ {"code":5002,"data":null,"msg":"请求过于复杂"}        HTTP 500

# 场景B：选了 1 条路径
curl -X POST -d '{"activePath":500,"selectedPaths":[500]}' ...
→ {"code":0,"data":{...}}                                HTTP 200

# 场景C：选了 3 条路径
curl -X POST -d '{"activePath":500,"selectedPaths":[500,501,502]}' ...
→ {"code":0,"data":{...}}                                HTTP 200
```

**根因链（机械可追）**：

1. `web/src/pages/CourseDetailPage.tsx:257`
   `enabled: selectedPaths.length > 0 || !!activePath`
   —— `|| !!activePath` 显式允许「有 activePath、无 selectedPaths」时发起请求。
2. 同文件 `:254`
   `selectedPaths: selectedPaths.length > 0 ? selectedPaths : undefined`
   —— 此时下发 `selectedPaths: undefined`。
3. `worker/src/modules/engine/engine.service.ts:188-190`
   `const targetPaths = selectedPathIds.length > 0 ? allLpRows.filter(...) : allLpRows;`
   —— 退化为**全部**学习路径。
4. 同文件 `:204-214`
   ```ts
   for (const tid of allTopicIds) {
     const t = await chapterRepo.getTopicById(c.db, tid);   // 循环内查库 = N+1
   ```
   —— 库内 `topics` 共 33 行，加上 `lpRepo.list` / `chapterCache.preload` / 进度查询。
5. `worker/src/data/db.ts:27`
   `throw new AppError(5002, 500, '请求过于复杂', { used: this.#used })`
   —— DbSession 语句预算 40 条，超限即抛。

**影响**：任何 localStorage 里存了 `engine.activePath` 但 `engine.selectedPaths` 为空的用户，**每次打开课程详情页都会打一次 500**。前端 `CourseDetailPage.tsx:260` `if (!engineQ.data ...) return null` 使 PathContextBar 静默消失——用户看不到报错，只是功能凭空少一块，符合 generated-code-failure-modes §2「沉默逻辑错误」特征。

**期望**：`selectedPaths` 缺省时不应退化为全量遍历；或 `getTopicById` 改批量 `WHERE id IN (...)` 一次取回（可将 33 条语句压到 1 条）。
