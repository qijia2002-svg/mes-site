## 1. 核心视觉隐喻：跟一张订单走完工厂

**不教「系统模块」，教「一个物件的旅程」。** 零基础学习者的认知锚点是「东西」，不是「架构」。
把 MES/ERP/WMS/QMS 从「四个系统」翻译成「一张订单在工厂里经过的六个工位」——系统名只是这些工位背后谁在记账，不是学习单位。

### 1.1 三句式讲法（无生活类比，用大白话 + 真实数据）

每一站的正文开头固定三句，顺序不可调：

1. **这是什么** —— 大白话讲清概念，不写「工厂像餐厅」这类生活类比（如：排产 = 把今天要做的活儿排个先后，决定哪张订单先开工）
2. **工厂里谁在做** —— 角色 + 真实动作（如：计划员在早会上把 3 张订单拆成 12 个工单，贴到看板上）
3. **系统里存哪张表** —— 落到真实数据（如：这 12 行就躺在 `work_order` 表里，每行一个工单号 `WO-20260801-02`）

整段正文会**频繁出现真实单号、表名、数字**（如 `WO-20260801-02`、计划 60 / 已完成 40），统一用「真实记录」内联样式（`--font-mono` + 中性色阶，见 `DESIGN.md` §3.5）与散文区分——**不靠颜色、不占 accent 配额**。

这条讲法同时解掉两个痛点：「太抽象」被第 1、2 句接住；「SQL 门槛高」被第 3 句消解——
**SQL 不再是一门要另外学的技能，只是「看一眼这个环节的记录长什么样」。**

### 1.2 节点视觉具象化：从「流程方块」到「单据卡」

现有 FactoryFlow 的抽象矩形对小白无信息量。改为**单据卡**形态：

- 顶部 3px `--phase-*` 色条（沿用四阶段语义色，仍不整卡填充）
- 单据号（mono + `tabular-nums`，如 `WO-20260808-014`）
- 一句人话标题 + 8px 状态点 + 文字状态（不靠颜色单独传意）

用户在学「看单据」，不是在学「看流程图」——这才是进车间后真实发生的事。

### 1.3 全景图降级：先给路，再给地图

`FactoryFlow v10`（四阶段泳道 / 12 节点）**保留但改定位**：
从「首页主入口」降为「第二层地图 / 复习视图」。

> 零基础要的是**路**，不是**地图**。一进来就给 12 节点全景 = 用信息量宣告「你还没入门」。
> 主线走完一遍后，全景图才从「劝退图」变成「原来我走过这些」的成就感载体。

**阶段划分暂缓（PM 更新 #2）**：tour/basics/deep 的节点划分待用户决策，先不定稿。
全景图节点视觉须同时支持两种布局，两种都留余地：
- **具象优先**（纯计算节点如 MPS/MRP 放靠后）→ 主线出现节点跳跃；跳过的节点**弱化但可见**（沿用 `--state-disabled-opacity` + `--meta` 文字，不隐藏），并配一句明示「此处暂跳过，走完主线再回来」。
- **业务流顺序**（按工单实际流转切）→ 无跳跃，不适用。

## 2. 首页 / 导航 / 进度重做

### 2.1 首页：单焦点，不是入口墙

**Variance 4 允许的唯一一处不对称**：左「继续学」大卡（2fr）+ 右 6 站阶梯（1fr）。

| 用户状态 | 大卡内容 |
|---|---|
| 零进度（首次进入） | 唯一入口：**「从这里开始：跟一张订单走完工厂」** + 一句「约 20 分钟走完第一站」+ `start` 图标按钮 |
| 有进度 | 下一站站名 + 一句人话说明「这一站你会搞懂什么」 + 动词按钮「继续第 3 站：排产」 |

**禁止**：营销 Hero、并排 4 个等尺寸入口卡、虚构指标（「10,000+ 学员」）、
「开启你的学习之旅」类空洞文案。首页是工作台，第一眼给的是**下一步动作**，不是标语。

### 2.2 6 站主线：唯一叙事轴

- **桌面**：左侧纵向阶梯（固定，随滚动常驻）
- **移动端**：顶部横向 chip 条，当前站居中自动滚入视野

三态视觉（**不新增任何色相**）：

| 态 | 视觉 | 图标 |
|---|---|---|
| `done` | `--surface` 底 + `--success` 描边环 + 文字 `--fg-2` | `success`（CircleCheck） |
| `current` | `--accent-soft` 底 + 2px `--accent` 左指示条 + 文字 `--fg` | `you-are-here`（MapPin） |
| `locked` | `--surface-2` 底 + `--state-disabled-opacity` + 文字 `--meta` | `lock`（Lock） |

**锁定态的标题必须可见**——可见不可入 = 制造方向感；标题也藏 = 制造神秘感与焦虑。
locked 站点点击不是死路：弹出一行「先完成第 2 站，这里会用到那边的工单概念」，给出**因果**而非拒绝。

### 2.3 进度：一处主进度 + 站内三点式（PM F10 锁定）

- **全站总进度「当前阶段完成度 + 总进度 N/12」**，主进度条只出现一处（顶栏下方或主线阶梯顶部，二选一，不重复）。
  N/12 的 **12 取自工厂全景 12 节点**（FactoryFlow v10）；6 站主线是面向学员的叙事分组，节点→站点映射待用户阶段决策后定稿。
  用 `--progress-track` / `--progress-fill`，完成后转 `--progress-fill-done`。
- **站内不用百分比**。用「知识 / 练习 / 测验」三点式微进度（3 个 8px 圆点，完成填充）。

> 为什么不用百分比：`67%` 对小白是噪音——他不知道 67% 意味着还剩多少事。
> 三个点是「还差两件事」，是**可数的、可完成的**。这是 Duolingo 单元结构最值钱的一点。

### 2.4 导航收敛：7+ → 4 项

工作记忆上限 ≤4 项。现有顶级导航砍到：

| 项 | 图标 | 说明 |
|---|---|---|
| 主线 | `paths` | 默认落地页，6 站学习主轴 |
| 工厂全景 | `factory` | 原首页，降为第二项 = 地图 / 复习 |
| 练习场 | `sql` | quiz + sql + sim 统一入口 |
| 我的 | `user` | 进度 / 收藏 / 设置 |

**术语表**不占导航位——并入全局搜索的一个 tab（小白查词是「遇到不懂的词」的即时行为，
属于 contextual disclosure，不该常驻在导航里跟主线抢注意力）。

## 3. 渐进披露四层（每层对应一种披露类型）

| 层 | 披露类型 | 落到哪个组件 | 治哪个痛点 |
|---|---|---|---|
| 1 站级锁定 | staged | 主线阶梯 | 不知从哪学起 |
| 2 章节分段 | progressive enabling | 章节正文 | 内容太密 |
| 3 提示阶梯 | contextual | 练习页 hint 按钮 | SQL 门槛高 / 挫败 |
| 4 深入折叠 | immediate vs progressive | `<details>` 折叠块 | 内容太抽象 |

### 3.1 站级锁定（staged）
未完成前一站 → 后一站 `locked`，标题可预览，点击给因果说明。见 §2.2。

### 3.2 章节内分段（progressive enabling）—— 治「内容太密」的主力

长文按三句式切成 **3 段**，一屏只呈现一段：

```
[第 1 段：这是什么]  读完 → 出现「继续」按钮
       ↓
[第 2 段：谁在做]    读完 → 出现「继续」按钮
       ↓
[第 3 段：存哪张表]  读完 → 出现「去动手」按钮（跳练习）
```

- 「继续」按钮出现用 `--dur-state` 的 opacity + 8px translateY，**无 bounce**。
- 已读段落不折叠回去（可向上回看），但视觉降权为 `--fg-2`，当前段 `--fg`。
- `prefers-reduced-motion` 下直接显示，不做位移。

> 关键：这不是把长文切碎，而是**把「读完了吗」这个判断从用户手里拿走**。
> 小白面对一屏 2000 字的第一反应是估算成本然后关掉；面对一屏 300 字是「这个我能读完」。

### 3.3 三级提示阶梯（contextual）—— Codecademy 最值钱的一条

练习页卡住时，`hint` 按钮**每点一次多给一级**，永不一次全给：

| 级 | 给什么 | 图标 | 文案示例 |
|---|---|---|---|
| 1 | 方向 | `hint` | 「想想：不合格品记录在哪张表？」 |
| 2 | 结构 | `hint` | 「用 `SELECT ... FROM inspection WHERE result = ?`，填空 `?`」 |
| 3 | 答案 + 讲解 | `answer` | 完整 SQL + 为什么这么写 + 常见错法 |

- 每级之间按钮文案递进：「给点提示」→「再具体一点」→「直接看答案」。
- 用到第 3 级**不扣分、不标记失败**——挫败感是零基础流失的第一原因，不是作弊风险。
- 已展开的提示保持展开，不折叠回去。

### 3.4 深入折叠（immediate vs progressive）

所有「进阶 / 为什么 / 边界情况」收进 `<details>`，默认收起，用 `deep-dive` 图标。

- ✅ 折叠标题写**具体问题**：「想深入：为什么工单要拆批次？」
- ❌ 禁止写「更多」「展开」「查看详情」——无信息量的触发器等于没有触发器。
- 折叠块底色 `--surface-2` + 1px `--border-soft`，不用 callout 的强调色（不占 accent 配额）。

## 4. 对标品牌与配色基调

### 4.1 四个对标，各取一件（只取结构，不取皮肤）

| 对标 | 取什么 | **明确不取什么** |
|---|---|---|
| **Duolingo** | 单一线性路径 + 锁定/解锁的方向感 + 单元级「还差几件事」 | 吉祥物、徽章雨、连胜施压、庆祝动画、彩色渐变 |
| **Khan Academy** | 单元级掌握度可视化、Explore 里「接着上次学」 | 学科墙式信息架构 |
| **Codecademy** | 三栏「讲解 / 动手 / 结果」+ checkpoint 即时判分 + 提示阶梯 | 付费墙式内容切割 |
| **Notion** | 长文的呼吸感、折叠块、行内代码的低干扰处理 | 无限嵌套的自由结构（小白需要固定骨架） |

**寄存器判据**：Learn 表面（主线 / 站页 / 章节）带轻 brand 成分——允许更大字号、更多留白、
更强的叙事感；Do 表面（SQL 沙箱 / 仿真 / 后台）严格 product 寄存器，维持工具密度。

### 4.2 配色：零新色相，完全沿用森林绿 v3

| Token | 值 | 本次角色 |
|---|---|---|
| `--accent` | `#547C70` | 唯一强调色，每屏 ≤2 处（current 站指示条 + 主 CTA） |
| `--bg` | `#F3F3E9` | 暖米底 —— **本身即「纸 / 教材」语义**，天然比冷白亲和 |
| `--success` / `--danger` | `#15803D` / `#B91C1C` | 判分，必须配图标 + 文字三重编码 |
| `--phase-*` | 四阶段 | 仍只做 3px 色条 / 8px 圆点，禁整卡填充 |

> 暖米底是本项目已有的、被低估的资产：v3 从冷白 `#f7f9fb` 换到暖米 `#F3F3E9` 之后，
> 页面读起来像「摊开的教材」而不是「后台管理系统」——这正好是零基础需要的心理安全感。
> **本次不需要为「亲和力」新增任何暖色，只需要停止把 Learn 表面当工具页排版。**

判分反馈**不引入新色**：`--success-soft` 底 + `success` 图标 + 「对了」文字；
`--danger-soft` 底 + `error` 图标 + 具体错因。禁止只靠颜色、禁止只写「答案错误」。

### 4.3 唯一结构性调整：双密度分区

现行全站 Density 6 对长文阅读过紧。**分区处理，不是全站放大**：

| 表面 | 密度 | 正文字号 | 行高 | 卡片 padding |
|---|---|---|---|---|
| **Learn**（主线 / 站页 / 章节 / 练习题面） | **3** | `--text-prose` 17px | `--leading-prose` 1.75 | `--space-6` 24px |
| **Do**（SQL 沙箱 / 仿真 / 后台 / 表格） | 6（不动） | `--text-base` 15px | `--leading-body` 1.55 | `--space-5` 20px |

实现方式：`data-density="learn"` 挂在 Learn 路由的布局容器上，覆写 `--card-padding` 等
既有 B-slot token，**不新增 token、不改 A1 层**。

### 4.4 动效纪律（Motion 3 不上调）

- 状态切换 `--motion-fast` 150ms；分段揭示 `--dur-state` 220ms（opacity + 8px translateY）。
- 解锁瞬间：`lock` → `unlock` 图标交换 + 卡片底色从 `--surface-2` 过渡到 `--surface`，**220ms，仅此而已**。
- 禁 bounce / elastic / 粒子 / 撒花 / >400ms 动效。`prefers-reduced-motion` 已全局兜底。

## 6. 页面级设计提示词方向

### 6.1 首页 `/`
- **布局**：`grid-template-columns: 2fr 1fr`，gap 24px。<1024px 单列，阶梯移到大卡下方。
- **核心组件**：ContinueCard（2fr）+ MainlineStepper（1fr）+ 顶部 N/12 主进度条（F10：当前阶段完成度 + 总进度 N/12）。
- **状态**：零进度 → ContinueCard 转 StartCard（`start` 图标 + 单一 CTA）；
  Loading → 大卡 skeleton；Error → 「读不到进度，重试」+ 按钮。
- **禁**：Hero、并排入口卡、虚构指标、`--text-3xl` 以上标题。

### 6.2 主线站页 `/line/:station`
- **布局**：中栏 `--container-prose` 720px 单列；左侧 MainlineStepper 常驻。
- **正文**：强制三句式三段（§3.2），段间 `--prose-gap`。
- **底部**：sticky「完成本站」条 + 下一站预告（`station` 图标 + 站名 + 一句预告）。
- **交互**：完成 → `unlock` 图标交换 + 下一站从 locked 转 current，220ms。

### 6.3 章节页 `/chapters/:id`
- **布局**：左 TOC（240px）+ 中正文（720px）+ 右「这一节你会」清单（可折叠）。
- **右栏清单**：3-4 条结果导向短句（「看懂一张工单上的 8 个字段」），完成打勾。
- **正文**：`example` 真实数据例子块 + `analogy` 对照块（车间动作 ↔ 系统记录，非生活类比）+ `deep-dive` 折叠块承载进阶。

### 6.4 练习页（quiz / sql 统一壳）
- **布局**：Codecademy 三栏 —— 左题面 + checkpoint 列表 / 中输入 / 右结果。
  <1024px 转上下两栏；<768px 转 Tab 切换。
- **判分**：即时，`success`/`error` 图标 + 文字 + 具体错因，**永不只回「答案错误」**。
- **提示**：三级阶梯（§3.3），按钮文案递进。
- **SQL 特殊**：沙箱维持 `--code-bg` 深色面板（Do 表面，Density 6 不变），
  但题面栏走 Learn 密度 —— 一屏内两种密度并置是刻意的，「读」和「写」视觉上分开。

### 6.5 工厂全景 `/factory`
- **定位改写**：从主入口 → 「地图 / 复习」。导航第二项。
- **节点**：改单据卡形态（§1.2）。已走过的站点用 `--success` 描边环。
- **首访引导**：若主线进度为 0，页面顶部一条说明「这是全貌图，建议先走完主线再回来看」+ 跳主线按钮。
