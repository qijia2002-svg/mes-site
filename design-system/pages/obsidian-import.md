## 0. 定位与受众

这是**运营侧工具**，使用者是内容维护者（你自己），不是学员。因此：

- **不进主导航**（`AppShell.tsx` 的 `PRIMARY_NAV` 保持 4 项不变），入口在后台内容管理页
- 密度可比学员侧再高一档，允许表格化、允许信息密集
- 但**反馈质量要求更高**：导入是**批量写库的破坏性操作**，一次误覆盖可能毁掉几十篇章节

导入类交互的第一设计原则：**在用户按下确认之前，把"将要发生什么"完整摊开。** 绝不做"选完文件夹直接入库"的一步式导入。

## 1. 流程总览：六态两步确认

```
[1 待导入] ──拖入/选择──▶ [2 拖悬停] ──放下──▶ [3 扫描中]
                                                   │
                                                   ▼
                                            [4 预览确认] ◀── 唯一的写库闸门
                                                   │ 确认
                                                   ▼
                                            [5 导入中] ──▶ [6a 完成]
                                                        └─▶ [6b 部分失败]
```

**闸门只有一个（态 4）**，它之前的所有操作都是只读的、可随时取消的。这个信息要通过文案传达给用户：扫描阶段的说明文字必须写「仅读取，不会改动站点内容」。

### 2.1 「说清读什么、不读什么」是本页最重要的一行字

Obsidian 库是用户的**私人笔记全集**，里面可能有日记、密码、未完成草稿。一个要求用户交出整个文件夹的界面，如果不说明读取边界，专业信任瞬间归零。

因此 12px 那行 `--meta` 说明文字是**功能性文案，不是装饰**，不许在后续迭代中被当作"次要信息"删掉。措辞规则：

- 正面列举读什么：`.md` 与 `attachments/` 内图片
- 负面列举不读什么：`.obsidian/` 配置、`.trash/`
- 不用「安全」「隐私保护」等承诺性形容词——**列举事实比形容词可信**

### 2.2 dashed 边框的例外说明

Master 未禁止 dashed，但全站几乎不用。此处用 dashed 是**语义性的**：虚线 = 「这个区域等待被填充」，是 dropzone 的跨产品通用语汇（与画布空态占位框同源）。**除 dropzone 与拖拽占位外，全站不得使用 dashed 边框。**

## 3. 态 2 · 拖悬停（dragover）

| 属性 | 从 | 到 | 时长 |
|---|---|---|---|
| 边框 | 2px dashed `--border-strong` | 2px **solid** `--accent` | `--motion-fast` 150ms |
| 底色 | `--surface-2` | `--accent-soft` | `--motion-fast` |
| 图标 | `--muted` | `--accent` | `--motion-fast` |
| 主文案 | 「把 Obsidian 库文件夹拖到这里」 | 「松手开始扫描」 | 立即切换 |

**禁止**：缩放、弹跳、边框流动动画（marching ants）、脉冲光晕。虚线转实线 + 底色变化已经足够清晰，其余都是噪音。

**拖入非法内容**（单个 `.md` 文件而非文件夹、或非文本文件）：
- 边框转 `--danger`，底 `--danger-soft`，文案「需要整个文件夹，不是单个文件」
- 松手后回到态 1，Toast 说明原因
- **不用 `--warn`**：这是明确的错误输入，不是警示

DropZone 塌缩为单行状态条，下方实时追加解析结果。**塌缩过程 `--motion-base` 220ms 高度过渡**，不做淡出重建（保持空间连续性）。

```

│ ████████████████░░░░░░░░░  已解析 47 / 68        13/mono│
│ 仅读取，不会改动站点现有内容              12/--meta     │
├─────────────────────────────────────────────────────────┤
│ ⟦chapter⟧ 01-生产模式/ETO与MTO对比.md      主题·章节    │
│ ⟦chapter⟧ 01-生产模式/离散vs流程制造.md    主题·章节    │
│ ⟦warn⟧    02-ERP/未命名 1.md              缺 title     │
│ ⟦chapter⟧ 02-ERP/BOM结构与层级.md          主题·章节    │
│                                       … 逐条追加        │
└─────────────────────────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 进度条 | 高 4px，`--progress-track` 槽 + `--progress-fill` 填充，`--radius-pill` |
| 计数 | mono + `tabular-nums`，**文件总数确定后才显示分母**；未确定时显示「已解析 47 个文件」不显示分母 |
| 文件行 | 32px 高，13px，路径 `--fg-2`，识别结果 `--meta` 右对齐 |
| 取消 | Ghost 按钮，全程可用 |
| 列表 | 最多显示最近 8 行，自动滚动到底；不做全量渲染 |

**进度条的诚实原则**：文件总数未知时**不许显示假的百分比进度**，用不确定态（indeterminate）或纯计数。伪造进度是最容易被察觉的不专业细节。

### 5.1 汇总卡

四格等宽，每格：20px mono 数字（`--weight-announce`）+ 13px 标签（`--muted`）。数字用语义色，标签用中性色——**色彩只落在数字上，标签保持中性**，避免整块彩色区域。

失败数为 0 时该格不显示（不显示「失败 0」——零值格是视觉噪音）。

### 5.2 表格

沿用 Master §4 数据表格规范：表头 `--table-header-bg` + 13px 510 sticky，行分隔 `--table-row-border`，hover `--table-row-bg-hover`。

冲突行整行 `--warn-soft` 底 + 行首 16px `warn` 图标；失败行 `--danger-soft` + `error` 图标。**图标 + 底色 + 「处理方式」列文字三重编码**，不单靠颜色（Master §8）。

### 5.3 冲突的逐行决策

覆盖行的「处理方式」是可操作下拉，三选项：

| 选项 | 说明 |
|---|---|
| **覆盖**（默认） | 用新内容替换现有章节正文 |
| **保留现有** | 跳过此文件 |
| **另存为新章节** | 标题追加 ` (导入 08-02)` |

顶部提供批量操作：「全部覆盖 / 全部保留」两个 Ghost 按钮，位于筛选行右侧。

### 5.4 Primary 按钮文案带实数

`确认导入 22 个文件` —— 数字随逐行决策实时变化。

这是反 AI 模板味的关键手法：`确认` / `提交` / `开始导入` 都是空洞动词，`确认导入 22 个文件` 让用户在按下前最后一次核对量级。若数字与心理预期不符（比如以为 20 篇结果显示 68），这一行字就拦下了一次事故。

### 5.5 空结果（Empty）

扫描完成但零个可导入文件：

```
⟦empty-search⟧ 48px --border-strong

这个文件夹里没有找到可导入的 Markdown

已扫描 68 个文件，其中 62 个在 .obsidian/ 配置目录内，
6 个是图片。课程内容需要 .md 文件，且首行有 title 字段。

[ 查看 frontmatter 格式要求 ]   [ 换一个文件夹 ]
      Ghost                        Secondary
```

同样四件套：会有什么 · 为何重要 · 如何开始 · 具体 CTA。**说清"扫了什么、为什么都不算数"**，而不是「未找到文件」。

```
│  │ 表格测试.md        正文为空                      │   │
│  │                                                 │   │

```

严格三段式（Master §7 Do 6）：
- **发生了什么**：3 个文件解析失败
- **为什么**：逐文件给出具体原因，不是「格式错误」
- **怎么修**：在 Obsidian 里补 title；并给「复制文件名列表」（用户要切回 Obsidian 找这些文件，复制列表是真实需要的动作）

**「修好后重试这 3 个」而非「重新导入」**——只重试失败项，不重跑已成功的 19 个。全有全无是导入工具最常见的设计失误。

## 9. 无障碍

| 项 | 要求 |
|---|---|
| 键盘 | DropZone `tabindex="0"` + `role="button"`，Enter / Space 唤起文件选择器。**拖拽绝不能是唯一通路** |
| 焦点 | DropZone `:focus-visible` 显示 `--focus-ring` |
| 状态播报 | 扫描 / 导入进度用 `aria-live="polite"`，每 10% 或每 5 个文件播报一次（不要每文件播报，会淹没读屏） |
| 完成播报 | `aria-live="polite"`：「导入完成，22 个文件，新增 18，覆盖 4」 |
| 失败播报 | `aria-live="assertive"` |
| 进度条 | `role="progressbar"` + `aria-valuenow/valuemin/valuemax`；不确定态用 `aria-busy="true"` 不带 valuenow |
| 表格 | `<th scope="col">`；处理方式下拉有 `aria-label="BOM结构.md 的处理方式"`（不能只有「处理方式」，读屏用户不知道是哪一行） |
| 动效 | 进度条填充在 reduced-motion 下不做宽度过渡，直接跳变；数值文字始终准确 |

## 11. 实现约束提示（给架构师 / 前端）

1. **文件夹选择的浏览器兼容分叉**：
   - Chromium：`showDirectoryPicker()`（File System Access API），体验最好
   - Safari / Firefox：回退 `<input type="file" webkitdirectory>`
   - 拖拽文件夹：`DataTransferItem.webkitGetAsEntry()` 递归读取
   - **必须做能力检测并回退**，不能只走 Chromium 路径
2. **扫描在主线程会卡死 UI**：文件数上千时，解析 frontmatter 应放 Web Worker，或分片 + `requestIdleCallback`
3. **进度必须真实**：文件总数在目录遍历完成后才确定，遍历期间用不确定态
4. **导入接口应支持部分成功**：返回 `{ succeeded: [], failed: [{file, reason}] }`，不要全有全无的事务语义
5. **`.obsidian/` 与 `.trash/` 必须在遍历层就跳过**，不是读进来再过滤——界面上承诺了不读取，实现要对得上
6. **图片附件处理策略需产品确认**：内联 base64 / 上传 R2 / 忽略。当前 `attachments/` 的文案承诺了会读取图片，若 v1 不做需同步改文案
