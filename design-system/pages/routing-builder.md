## 0. 一句话定位

一块能把「工艺路线」这个抽象名词变成**可以用手排、可以按下去看它跑起来、跑错了会当着你的面堵住**的画布。它不是流程图绘制工具（那是 Visio 干的事），它是**带执行语义的教学沙盒**——图排完就能跑，跑起来会出事，出事有解释。

## 1. 对标调研：Scratch / TurboWarp 的积木语言，哪三条要借、哪四条必须扔

### 1.1 调研结论先行

Scratch 的成功不在"积木好看"，在于它用**视觉形状承载了语法规则**，从而让初学者不可能写出语法错误。这套认知脚手架是可迁移的；而承载它的那层皮肤（拟物拼图 + 九色高饱和分类 + 卡通圆润）是**为 8 岁儿童做的情绪设计**，迁到制造业数字化语境里会直接摧毁专业可信度。

因此本项目的策略是一句话：

> **借 Scratch 的教学法，扔 Scratch 的皮肤；视觉语言改投「专业节点图谱」谱系（Node-RED / n8n / Simulink / BPMN 工艺流程图）。**

图形化编程工具存在清晰的两个谱系，选错谱系就是选错受众：

| 谱系 | 代表 | 视觉语汇 | 目标用户 | 本项目取舍 |
|---|---|---|---|---|
| 教育启蒙 | Scratch / Blockly | 拼图榫卯、9 类高饱和分类色、卡通圆角、音效 | 儿童 / 零基础 | **取教学法，弃视觉** |
| 工程 / 流程编排 | Node-RED、n8n、LabVIEW、Simulink | 矩形节点 + 端口 + 连线、中性 chrome、状态色克制 | 工程师 / 实施顾问 | **取视觉语汇** |
| 业务流程建模 | BPMN 2.0 / Visio 工艺流程图 | 正交折线、泳道、标准图元 | 制造业本行 | **取连线形态与命名** |

我们的学员是**MES 实施 / 运维 / 求职者**，不是儿童。他们上班后要面对的是 Visio 画的工艺流程图和 MES 后台的路线配置界面。界面越接近他们未来的真实工作面，迁移价值越高。

### 1.2 借的三条（认知脚手架，全部保留）

**借 1 · 形状即语法，可连接性可见**

Scratch 用 hat（帽子块，只能在顶）/ stack（凹凸榫，上下可接）/ boolean（六边形，只能塞进六边形槽）/ cap（平底，后面接不了东西）这套形状系统，让"什么能接什么"不用查文档——手拿过去，能不能接一眼就知道，语法错误在物理上不可能发生。

**工业化转译**：不做拼图榫卯，改做**端口（Port）**。
- 工序卡左边缘有一个 IN 端口（入料），右边缘有一个 OUT 端口（出料）
- 有端口 = 可连接；没端口 = 不可连接。例如「入库」类终结工序**不画 OUT 端口**，学员就永远不会把入库接到机加工前面
- 拖连线时，合法目标端口放大并填充 `--accent`，非法目标**完全不响应**（不变红、不抖动——错误不该被表演，它该被阻止）

这一条是三条里最值钱的：它把"工艺路线的合法性规则"从文档里搬进了手感里。

**借 2 · 三分区空间隐喻（Palette → Stage → Result）**

Scratch / Blockly / Node-RED / n8n 无一例外都是「左侧素材库 → 中间画布 → 结果区」。这是被上亿用户验证过的空间模型，学员的肌肉记忆可以直接复用。本项目沿用：左 `工序库` / 中 `画布舞台` / 右 `参数检查器`（选中才出现） / 底 `运行时间轴`（运行才展开）。

**借 3 · 运行时高亮：把不可见的执行状态变成可见的空间位置**

Scratch 运行中的脚本外围有一圈黄色发光框，学员一眼知道"现在跑到哪了"。这是 Scratch 教学效力的核心——**它让"程序在执行"这件抽象的事获得了空间坐标**。

**工业化转译**：工单小球沿连线流动 + 当前工序卡描边 + 底部时间轴同步步进。三重冗余表达同一件事（位置 / 描边 / 列表），任一通道失效（色盲、reduced-motion、屏幕阅读器）都还剩两条。详见 §5。

### 1.3 扔的四条（幼稚感来源，逐条替换）

**扔 1 · 拟物拼图榫卯 → 矩形卡片 + 端口 + 正交连线**

榫卯是"玩具"的能指。工业界的能指是矩形框 + 箭头。

连线形态特别说明：**用正交折线（拐直角），不用贝塞尔曲线**。n8n / Node-RED 用曲线，但那是 IT 自动化工具的娱乐化表达；制造业受众在 Visio、CAD 工艺卡、车间白板上看到的一律是直角折线。折角给 4px 圆角软化，不做尖角。**这是本土化最关键的一处形态决策**。

**扔 2 · 九类高饱和分类色 → 中性卡片 + 颜色只承载状态**

Scratch 用 9 种饱和色（动作蓝 / 外观紫 / 声音玫红 / 事件淡黄 / 控制橘 / 侦测天蓝 / 运算绿 / 变量桔红 / 自定义红）区分类别。这在本项目里有三重问题：

1. 直接违反 Master §2「每屏 `--accent` 可见使用 ≤2 处」与「中性色 85%」的配色纪律
2. 紫 / 玫红命中 P0-2 红线色域
3. 用颜色编码"类别"，就没有颜色留给编码"状态"了——而在仿真沙盒里，**状态（待运行 / 运行中 / 已完成 / 异常）远比类别重要**

**替换方案**：卡片一律 `--surface` 白底 + `--border` 描边。
- **类别**由图标 + 文字承载
- **颜色**只承载状态：`--accent` = 运行中，`--success` = 已完成，`--danger` = 异常，中性 = 待运行

**扔 3 · 卡通圆角与厚描边 → 沿用项目卡片规格**

工序卡圆角一律 `--radius-md`（12px，项目卡片上限），描边 1px，遵守 Hairline First。不加大圆角、不加粗描边、不做拟物高光。

**扔 4 · 音效与弹跳缓动 → 静默 + `--ease-standard`**

Scratch 吸附时有"咔哒"音效、放置有弹跳。本项目：**零音效**（车间/办公环境不合适，且无障碍上是干扰），缓动一律 `--ease-standard`，**明令禁止 bounce / elastic**（Master §7 Don't 9）。

### 1.4 TurboWarp 给的一条旁证

TurboWarp 与 Scratch 共用同一套 Blockly 语法内核，但换上中性深色 chrome 后，观感立刻从"儿童编程"偏向"开发者工具"。这反向证明了本文的核心判断：**幼稚感来自 chrome（外壳配色与质感），不来自积木语法本身。** 我们保留语法、重做 chrome，方向成立。

我们不抄 TurboWarp 的深色——本项目是浅色 product 寄存器，深色是 SQL 面板的专属身份（Master §1），画布再用深色会稀释那处身份。我们的"成年化"手段是**去分类色 + 中性化**，不是暗色化。

### 1.5 命名本土化（文案即视觉的一部分）

术语直接决定专业感，全项目统一：

| 禁止用 | 必须用 | 理由 |
|---|---|---|
| 积木 / 模块 / 方块 | **工序卡** | 「工序」是 MES 标准术语 |
| 搭建 / 拼装 | **编排 / 排线** | 行业动词 |
| 运行 / 播放 | **投产运行** | 「投产」是车间语言 |
| 小球 / 精灵 | **工单** | 流动的实体就是工单本身 |
| 报错 / Bug | **异常工序 / 停线** | MES 语义 |
| 画布 | **画布舞台**（对内）/ **工艺路线图**（对学员） | 面向学员的文案不暴露实现词 |

Master §7 Don't 10 已明令：面向学员的文案不出现实现细节。同理，也不出现编程教育黑话。

**图标分配规则（重要，防止前端擅自扩充）**

工序图标按**四大类**分配，不按具体工序名分配：

| 大类 | Icon 语义名 | lucide | 覆盖工序示例 |
|---|---|---|---|
| 备料 | `material` | Package | 下料、领料、备料 |
| 加工 | `equipment` | Cog | 机加工、焊接、热处理、打磨 |
| 装配 | `bom` | Boxes | 装配、总装、部装 |
| 质检 | `quality` | ShieldCheck | 首检、巡检、终检、出厂检 |
| 未归类 | `process` | Milestone | 兜底 |

「机加工」和「焊接」共用 Cog 图标是**有意为之**，不是遗漏：图标承载**类别**，文字承载**实例**，图标不该重复文字已经说清楚的事。这样做的收益是 Icon.tsx REGISTRY 不会随工序库扩充而无限膨胀。**前端不得为单个工序申请专属图标。**

### 3.4 渐进式引导（不做遮罩式 Tour）

遮罩 Tour 打断任务且是典型 AI 模板味，改用三步渐进披露，**每步只教一件事**（对齐认知负荷「一次一事」）：

| 触发时机 | 提示 | 形式 |
|---|---|---|
| 画布为空 | 空态四件套 | 空态区 |
| 放下第 1 张卡 | 右侧 64px 处出现 dashed 占位框 +「拖到这里会自动连线」 | 画布内 ghost，13px `--meta` |
| 卡片数 ≥2 | 运行按钮由 disabled 转 enabled，一次性 tooltip「⌘/Ctrl + Enter 也能投产」 | Tooltip，`--elev-dropdown`，5s 后消失，localStorage 记忆只显示一次 |

## 4. 拖拽交互视觉反馈规范

### 4.1 工序卡状态矩阵（9 态全覆盖）

| 状态 | 描边 | 底色 | 阴影 | 变换 | 光标 | 时长 |
|---|---|---|---|---|---|---|
| **常态** | 1px `--card-border` | `--surface` | `--elev-card` | 无 | `grab` | — |
| **悬停** | 1px `--card-border-hover` | `--surface` | `--elev-card-hover` | `translateY(-1px)` | `grab` | `--motion-fast` |
| **聚焦**(键盘) | 1px `--card-border` | `--surface` | `--focus-ring` | 无 | — | `--motion-fast` |
| **选中** | 2px `--accent` | `--surface` | `--elev-card` | 无 | `grab` | `--motion-fast` |
| **拖起** | 1px `--card-border-hover` | `--surface` | `--elev-modal` | `scale(1.02)` | `grabbing` | `--motion-instant` |
| **原位占位** | 1px dashed `--border-strong` | `--surface-2` | 无 | 无 | — | 立即 |
| **不可连接** | 1px `--border-soft` | `--surface` | 无 | 无 | `not-allowed` | `--motion-fast` |
| **运行中** | 2px `--accent` | `--accent-soft` | `--elev-card` | 无 | — | `--motion-fast` |
| **已完成** | 1px `--success-border` | `--surface` | `--elev-card` | 无 | `grab` | `--motion-fast` |
| **异常** | 2px `--danger-border` | `--danger-soft` | `--elev-card` | 无 | `grab` | 见 §5.3 |

设计说明：
- **悬停态刻意与现有 `.card-link:hover` 完全一致**（`--card-border-hover` + `--elev-card-hover` + `translateY(-1px)`，见 `styles.css:372-375`）。搭建器不是孤岛，卡片的手感必须和全站一样
- **拖起用 `scale(1.02)` 不用 `rotate`**。旋转是 Trello / Scratch 的玩具感表达，制造业语境里一张倾斜的工序卡等于"这张卡出问题了"
- **选中用 2px `--accent` ring，不改底色**；运行中用 `--accent-soft` 底。两者必须视觉可分——学员会同时遇到"我选中了它"和"它正在跑"
- **不可连接态用降低描边对比表达，不用红色**。红色是"错误"，而"这里接不上"不是错误，是规则

### 4.2 拖拽全流程时序

**阶段 1 · 拾起（mousedown → 位移 >4px）**
- 4px 位移阈值防误触（点击选中 vs 拖动移动）
- 卡片转拖起态，`--motion-instant` 80ms
- 原位立即出现 dashed 占位框
- 画布网格点由 `--border-soft` 提升为 `--border`（网格变清晰，辅助对位）——这是唯一一处"拖拽时画布响应"的表达，克制

**阶段 2 · 移动中**
- 卡片跟随光标，**无延迟无缓动**（跟手是拖拽体验的第一要务，任何 lerp 都会被感知为卡顿）
- 吸附网格 24px（`--canvas-grid-size`），按住 `Alt` 临时关闭吸附做自由摆放

**阶段 3 · 吸附预览（进入某个插入点 40px 半径）**

这是整个拖拽体验里信息量最大的一帧，分两种情形：

| 情形 | 视觉表达 |
|---|---|
| 插入到两卡之间 | 该段连线**从中间断开撑出 200px 空隙**（`--motion-fast` 150ms），空隙内显示 2px `--accent` dashed 占位框；两侧卡片平移让位 |
| 追加到末端 | 末端 OUT 端口放大至 12px 并填充 `--accent`，向右伸出一段 2px dashed `--accent` 预备连线 |
| 悬停在非法区域 | 无任何响应（占位框不出现），卡片保持拖起态 |

**「撑开让位」是本设计的关键手感**——它让"插入"这件事在放手之前就被完整预演了，学员不需要放手后才知道结果。这是从 Scratch 吸附预览借来的，但换成了正交连线语汇。

**阶段 4 · 放下**
- 卡片落位，`--motion-fast` 150ms `--ease-standard` 归位到网格
- 连线自动重连并重排编号（010/020/030 自动重算，工序号是位置的函数，不是用户输入）
- 占位框消失
- **无成功音效、无粒子、无庆祝动画**

**阶段 5 · 拖出画布（删除）**
- 拖到画布外，卡片 `opacity .45` + 光标 `not-allowed`
- 放手不直接删除，而是**回弹归位 + Toast「工序卡已移出路线」+ 撤销按钮**（破坏性操作必须可逆）

### 4.3 连线（FlowLink）规范

| 状态 | 线宽 | 颜色 | 箭头 | 附加 |
|---|---|---|---|---|
| 常态 | `--link-w` 1.5px | `--border-strong` | 6px 实心三角 | — |
| 悬停 | `--link-w-active` 2px | `--accent` | 同色 | 中点浮出 20px 删除按钮（`delete` 图标，`--surface` 底 + `--elev-dropdown`） |
| 拖拽创建中 | 2px dashed | `--accent` | 跟随光标 | 合法端口放大填充；非法端口无响应 |
| 运行流经 | 2px | `--accent` | 同色 | 小球在其上 |
| 已流过 | 1.5px | `--border-strong` | — | **不变色**——进度由小球位置表达，不需要连线再说一遍 |

形态规则：
- **正交折线**，拐角 4px 圆角（见 §1.3）
- 水平优先：出 OUT 端口先水平走 32px，再垂直，再水平入 IN 端口
- 蛇形折行时的回折线走画布右/左侧 24px 留白通道，**不穿越任何卡片**
- 连线不允许交叉时自动加 4px 跨桥（半圆跳线，Visio 惯例）

### 4.4 工序库（Palette）项

- 尺寸 168×44（比画布卡小一号，暗示"这是素材不是实例"）
- 常态：`--surface-2` 底 + 无描边 + 16px 图标（`--muted` 色，光学补偿规则）+ 13px 文字
- 悬停：`--surface-3` 底 + 图标转 `--fg-2` + 右侧浮出 `add` 图标
- 拖起：生成半透明幽灵跟随（`opacity .8`），原项**保持原位不消失**（素材库是无限的，这一点必须视觉说清）
- **双击 / Enter = 追加到路线末端并自动连线**——这是零拖拽通路，同时也是鼠标用户的快捷路径（见 §7 无障碍）

### 4.5 分组与认知负荷

工序库固定 **4 组**（备料 / 加工 / 装配 / 质检），每组展开后 ≤6 项，同时只允许展开 1 组（手风琴）。任一时刻可见选项 ≤6，落在工作记忆 4–7 的安全区内。

工具条可见控件 5 个（运行 / 暂停 / 单步 / 速度 / 视图），撤销重做归为一组视觉单元。超出的（导出、清空、另存模板）收进 `more` 菜单。

## 5. 运行态动效规范

### 5.1 动效预算豁免声明（必读，否则会被判违规）

Master §7 Don't 9 规定「禁止 >500ms 动效」，`--motion-slow` 上限 320ms。**仿真回放不适用该上限**，理由：

1. 该规则约束的是 **UI 动效**（界面对操作的反馈），其价值在"快到无感"
2. 仿真回放是**内容动画**（data animation），它本身就是被观看的内容——如同视频播放不受 300ms 约束
3. 它由用户**主动触发**、可暂停、可单步、可调速，不构成强加等待

**豁免边界（严格，超出即违规）**：
- 仅限 `.canvas-stage` 内的工单小球位移与工序驻留
- **必须**提供速度控制（0.5× / 1× / 2×）+ 暂停 + 单步
- 画布内的所有 **UI 反馈**（hover / 选中 / 面板 / 气泡出现）仍严守 ≤320ms
- 无用户触发时画布**零动效**——不做待机呼吸、不做背景流光

### 5.2 工单小球（WorkOrderToken）

| 属性 | 规格 | Token |
|---|---|---|
| 直径 | 12px（桌面）/ 14px（coarse 指针） | `--token-size` |
| 填充 | `--accent` | |
| 描边 | 1.5px `--surface` | 在连线上形成分离 |
| 光环 | `0 0 0 4px var(--accent-soft)` 实心 ring | **不用 blur glow**，Hairline First |
| 标签 | 小球右上 12px mono `--meta` 显示工单号 `WO-2041`，缩放 <70% 时隐藏 | `--font-mono` |

**节奏（1× 基准）**

| 阶段 | 时长 | 缓动 | 视觉 |
|---|---|---|---|
| 沿连线移动 | `--sim-step-move` 900ms | `linear` | 小球匀速。**物流是匀速的，加减速会读作"犹豫"** |
| 工序内驻留 | `--sim-step-dwell` 600ms | — | 卡片转运行中态；底部 2px 进度条 0→100% |
| 段间衔接 | 0ms | — | 无停顿，驻留结束立刻出发 |

五道工序总时长 ≈ 900×4 + 600×5 = 6.6s。0.5× 挡 13.2s（讲解用），2× 挡 3.3s（复看用）。

**为什么驻留用进度条不用 spinner**：spinner 表达"不知道要多久"，进度条表达"加工需要 12 分钟标准工时，现在过了 60%"。后者才是 MES 语义。进度条宽度 = 卡片宽，高 2px，贴卡片底边，`--accent` 填充 `--surface-3` 槽。

### 5.3 异常工序（标红闪烁）

**触发**：小球抵达故障注入工序时。

**时序**（严格按此顺序，不许同时发生——同时发生会互相抢注意力）：

| t | 事件 | 规格 |
|---|---|---|
| 0ms | 小球停在该工序 IN 端口，填充由 `--accent` 转 `--danger`，光环转 `--danger-soft` | `--motion-fast` |
| 0ms | 卡片转异常态：2px `--danger-border` + `--danger-soft` 底 | `--motion-fast` |
| 0–3600ms | **闪烁 3 次后停止**，周期 `--sim-fault-blink` 1200ms，`opacity` 在 `1 ↔ 0.55` 间往返 | `--ease-standard` |
| 3600ms | 停在**静态高亮态**（不再闪），卡片右上角出现 16px `warn` 图标 `--danger` 色 | — |
| 3800ms | 解释气泡淡入 | `--motion-base` 220ms |
| 同时 | 后续工序转 `--muted` 降饱和 + 连线转 dashed，表达「后面堵住了」 | `--motion-base` |

**关键约束：闪烁必须有次数上限（3 次）。** 无限闪烁是三重罪——前庭敏感人群的生理不适、注意力持续劫持、以及"这界面坏了"的观感。闪 3 次足够抓住注意力，之后由静态高亮 + 图标承载状态。

**「后续工序降饱和 + 连线虚化」是本设计的教学高光**：它让"一道工序停了，整条线都停了"这个 MES 核心痛点，在视觉上一秒说清。这比任何文字说明都有效，也正是路线图 §2 要的「模拟流程出错带来的业务问题」。

### 5.4 解释气泡（FaultBubble）

```

   ┌──────────┐    ◤│ ⟦danger⟧ 焊接工序缺料停线   15/590│
   │◧ 焊接 030│─────│                                  │

   └──────────┘     │ 焊接工单要求 100 件，差 20 件。  │
    异常态           │ 缺料时工单无法报工，整条线在此   │
                    │ 停住，后面 2 道工序全部等待。    │
                    │                        13/--fg-2 │
                    │ ┌────────────┐ ┌──────────────┐ │
                    │ │ 查看解决方案│ │ 补料后重跑   │ │
                    │ └────────────┘ └──────────────┘ │
                    │    Ghost           Secondary     │
                    └──────────────────────────────────┘
```

| 属性 | 规格 |
|---|---|
| 宽度 | `max-width: 280px`，自适应 |
| 底 / 描边 / 圆角 | `--surface` / 1px `--danger-border` / `--radius-md` |
| 阴影 | `--elev-dropdown`（气泡是浮层，允许阴影） |
| **禁止** | 毛玻璃。Master §6：除 topbar / tabbar 外全站禁装饰性 blur |
| 位置 | 卡片右侧 12px，空间不足则上方；8px 三角指向卡片 |
| 出现 | `--motion-base` 220ms，`opacity` + `translateX(-4px)→0`。**不做 scale 弹出** |
| 关闭 | Esc / 点击外部 / 右上 `close` 按钮。**不自动消失**（Master §4：error 不自动消失） |

**文案严格三段式**（Master §7 Do 6）：发生了什么（缺料停线）+ 为什么（80 件 vs 100 件，差 20）+ 怎么修（两个按钮）。

数字用 mono + tabular-nums。用具体数字「80 / 100 / 20 / 2 道」而非「部分物料不足」——具体性是反 AI 模板味的第一道防线。

### 5.5 运行时间轴（RunTimeline）

底部 88px，运行时展开。横向步进条，每道工序一格：

```
┌─────────────────────────────────────────────────────────────┐
│ ●───────●───────●───────◆- - - -○- - - -○      00:04.2 / 06.6│
│ 下料    机加工   焊接    质检     装配                        │
│ 已完成  已完成   已完成  异常     等待                        │
└─────────────────────────────────────────────────────────────┘
```

- 已完成 `--success` 实心点 / 当前 `--accent` / 异常 `--danger` 菱形 / 等待 `--border-strong` 空心点
- **状态同时用形状 + 颜色 + 文字三重编码**（Master §8：状态不单靠颜色）
- 点击任一格 = 跳转到该步（可回看，教学必需）
- 时间用 mono tabular-nums

时间轴是 reduced-motion 下的**主要状态通道**（见 §5.6），因此它不是装饰，是可访问性基础设施。

### 5.6 prefers-reduced-motion 降级（P0 级要求）

**警告：不能只依赖 CSS 全局兜底。** `design-tokens.css:364-372` 的全局兜底会把 `animation-duration` 压到 `0.01ms`，这会导致整段仿真在一瞬间跑完——**用户什么都没看到，功能等于失效**。这不是降级，是破坏。

**因此仿真引擎必须用 JS 主动检测并切换模式**：

```
matchMedia('(prefers-reduced-motion: reduce)').matches → 步进模式
（并监听 change 事件，运行中切换要即时生效）
```

| 元素 | 标准模式 | 步进模式（reduce） |
|---|---|---|
| 工单小球 | 沿连线 900ms 匀速位移 | **不位移**。直接出现在下一工序 IN 端口，`opacity` 150ms 淡入淡出 |
| 节奏 | 900 移动 + 600 驻留 | 每步固定停留 **1200ms**（总时长保持相近，理解节奏不变） |
| 工序驻留进度条 | 宽度 0→100% 动画 | 不做动画，显示离散文字「60%」 |
| 异常闪烁 | 闪 3 次 | **完全不闪**，直接静态 `--danger` 高亮 + 图标 |
| 解释气泡 | 220ms 淡入 | 立即出现，无过渡 |
| 后续工序降饱和 | 220ms 过渡 | 立即切换 |
| 时间轴 | 同步步进 | 同步步进（**此模式下的主要状态通道**） |
| 自动滚动 | `behavior: 'smooth'` | `behavior: 'auto'` |

**核心原则：reduced-motion 降级的是"运动"，不是"信息"。** 每一步发生了什么，两种模式下的可获知信息必须完全等价。

## 6. 移动端降级方案

### 6.1 决策：<768px 不做自由画布

三条硬理由：

1. **手势冲突不可解**：触摸表面上，「拖动卡片」与「平移画布」是同一个手势（单指按下拖动），无法可靠区分意图。业界解法（长按进入拖动模式）会让每次移动都多付 200ms 等待，在需要反复调整的编排场景里体验崩塌
2. **空间不够**：375px 屏幕减去 gutter 12×2 = 351px 可用宽，一张 200px 工序卡 + 64px 连线 = 264px，一行放不下两张。自由二维布局在此宽度下失去意义
3. **端口不可点**：8px 端口在触屏上远低于 44px 最小目标；放大到 44px 后，端口本身就比卡片高度的一半还大，视觉破产

### 6.2 替代方案：纵向步骤列表（不是"简化画布"，是同构表达）

工艺路线的本质是**有序序列**。二维画布是它的一种表达，纵向列表是另一种**信息等价**的表达——不是阉割版。这是本方案的核心论点：移动端用户拿到的不是"残废的画布"，是"更适合竖屏的同一件东西"。


### 6.3 移动端交互细则

| 交互 | 方案 |
|---|---|
| **排序** | 长按 grip 手柄 200ms 进入拖动，行转 `--elev-modal` + `scale(1.01)`，其余行 `translateY` 让位（150ms）。**只在 grip 上触发，行本体保持可滚动** |
| **连线** | 不需要手动连。相邻两行天然顺序连接，间隙里画 2px `--border-strong` 竖线 |
| **插入** | 间隙中点 24px `⟦add⟧` 按钮（命中区 44px），点击在此位置插入 |
| **添加** | 底部全宽 Primary → 底部 **ActionSheet**（不用居中 Modal），按 4 组列出工序 |
| **编辑参数** | 点击行本体 → 底部 Sheet 展开参数表单 |
| **删除** | 左滑露出 `--danger` 删除按钮（88px），需二次确认；或 Sheet 内删除 |
| **分支** | 缩进 16px + 左侧竖线分叉，**最多 1 层**。超过 1 层显示「这条路线有 2 层分支，请在电脑上编辑」并转只读 |
| **运行** | 小球沿竖线**向下**移动（纵向同样成立），当前行高亮 + `scrollIntoView({block:'center'})`，行为受 reduced-motion 控制 |
| **异常** | 该行转 `--danger` 态，解释**内联展开在行下方**（浮层气泡在小屏会遮挡上下文） |

### 6.4 断点与指针能力分离（关键工程约束）

**布局按宽度判断，手势能力按指针类型判断。** 两者不可混用——iPad 有精确指针但宽度中等，触屏笔记本宽度大但指针粗糙。

| 条件 | 生效内容 |
|---|---|
| `@media (max-width: 767px)` | 切换为纵向步骤列表 |
| `@media (min-width: 768px)` | 画布模式 |
| `@media (pointer: coarse)` | 端口命中区 8→44px；工单小球 12→14px；grip 44×44；所有按钮 min-height 44px（全局已有兜底） |
| `@media (min-width: 768px) and (pointer: coarse)` | 画布模式 + 触摸增强：端口放大、双指平移、pinch 缩放、长按 200ms 拖卡片 |

### 6.5 底栏避让

沿用现有约定，与 `styles.css:1096` 一致：

```
内容容器 padding-bottom: calc(var(--tabbar-h) + var(--space-4))
吸底运行条 bottom: calc(var(--tabbar-h) + env(safe-area-inset-bottom, 0))
```

吸底运行条使用与 tabbar 同款玻璃（`--glass-bg` / `--glass-border` / `--glass-blur`），两条横条视觉同族，不出现两种材质。

### 6.6 桌面画布的缩放与平移

| 操作 | 手段 |
|---|---|
| 平移 | 空格 + 拖 / 中键拖 / 触控板双指 |
| 缩放 | Ctrl + 滚轮 / 触控板 pinch，范围 **50%–150%** |
| 归位 | 工具条「适应画布」（`fit-view`），快捷键 `Shift + 1` |

**不做无限画布**。边界设为 1.5 屏，越界时橡皮筋阻尼回弹（阻尼，非 bounce 缓动）。工艺路线是有限对象，无限画布只会让人迷路。

## 7. 无障碍：拖拽的键盘与读屏通路

拖拽交互是无障碍高危区。本模块**必须**提供完整的零拖拽通路——不是补丁，是平行的一等公民路径。

### 7.1 键盘操作全集

| 按键 | 行为 |
|---|---|
| `Tab` | 在 工序库 → 画布卡片 → 工具条 间循环，顺序与视觉顺序一致 |

| 卡片 `Shift + 方向键` | 微调 4px |
| 卡片 `Enter` | 进入连线模式 → `Tab` 在候选目标间循环（候选高亮）→ `Enter` 确认 → `Esc` 取消 |
| 卡片 `Delete` | 删除（Toast + 撤销） |
| `Ctrl/Cmd + Z / Shift+Z` | 撤销 / 重做 |
| `Ctrl/Cmd + Enter` | 投产运行 |
| `Space` | 运行中暂停 / 继续 |
| `→`（运行暂停时） | 单步 |

### 7.2 屏幕阅读器

- 画布 `role="application"` + `aria-label="工艺路线画布，共 5 道工序"`
- 每卡 `aria-label="工序 030 焊接，设备 WD-02，前序 机加工，后序 质检"`——**前后序关系必须念出来**，这是连线的唯一读屏等价物
- 运行进程 `aria-live="polite"`：「工单 WO-2041 流转至 焊接 工序」
- 异常 `aria-live="assertive"`：「焊接工序异常，缺料停线，后续 2 道工序等待」
- 时间轴用 `<ol>` 语义列表，每项 `aria-current="step"` 标记当前

### 7.3 对比度复核（针对 v2 主色 --accent 重算）

> 审计记录值：v2 主色 `--accent`（取值见 design-tokens.css，替代旧青色 `--accent`）。下文比值基于该取值核算。

## 10. Do / Don't（本模块专属，Master 之外的增量）

**Do**

1. 工序卡 hover 手感与全站 `.card-link` 完全一致，不为搭建器另造一套
2. 颜色只承载状态（待运行 / 运行中 / 已完成 / 异常），类别由图标 + 文字承载
3. 连线一律正交折线，折角 4px 圆角
4. 异常闪烁封顶 3 次，之后转静态高亮
5. 仿真必须 JS 主动检测 `prefers-reduced-motion` 切换步进模式，不得只依赖 CSS 兜底
6. 每个破坏性操作（删卡、清空、覆盖）都要 Toast + 撤销
7. 工序号 010/020/030 由位置自动推导，不让用户手填
8. 所有数字（工时、件数、工单号、计时）走 mono + `tabular-nums`
9. 移动端提供与画布**信息等价**的步骤列表，不是阉割版

**Don't**

1. 拼图榫卯、气泡形状卡片、任何拟物积木造型
2. 按工序类别分配彩色卡片底（Scratch 九色模式）
3. 拖起时旋转卡片（Trello / Scratch 玩具感）
4. 贝塞尔曲线连线（IT 工具语汇，非制造业语汇）
5. 无限闪烁、呼吸灯、待机流光、背景粒子
6. 吸附 / 放置 / 完成音效
7. bounce / elastic / spring 缓动
8. 气泡或工序卡使用毛玻璃（玻璃只属于 topbar / tabbar / 移动端吸底运行条）
9. 运行完成的庆祝动画、撒花、成就弹窗（Master §1 反目标：不做消费级学习 App）
10. 面向学员的文案出现「节点」「Canvas」「状态机」「实例」等实现词
11. 为单个工序申请专属图标（图标承载类别，不承载实例）
12. 移动端用长按整行触发拖动（会杀死列表滚动）

## 11. 落地约束提示（给架构师 / 前端）

1. **路由级 lazy 必需**：仿真引擎 + 画布是重模块，必须 `React.lazy` + `Suspense`，不进首屏 chunk（对齐路线图 §2 P0）
2. **连线用 SVG 单层覆盖，不用逐条 DOM**：一个 `<svg>` 铺满画布，所有 `<path>` 在内，卡片用绝对定位 DOM 浮在其上。混用会导致层级与命中区打架
3. **仿真时钟不要用 CSS animation 驱动业务状态**：CSS 动画无法暂停到任意帧、无法单步、无法被 reduced-motion 安全降级。用 `requestAnimationFrame` + 状态机驱动，CSS 只负责视觉过渡
4. **`matchMedia` 要监听 `change`**：用户可能在仿真运行中切换系统偏好，需即时切模式
5. **拖拽建议用 Pointer Events 统一鼠标 / 触摸 / 笔**，避免 mouse + touch 双套逻辑
6. **撤销栈**：编排类工具没有撤销不可用。建议命令模式，栈深 ≥20
7. **`--radius-lg` 已是 16px**：气泡 / Sheet 用 `--radius-md` 12px，避免触碰"过度圆角"上限
